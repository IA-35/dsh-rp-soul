# dsh-rp-soul

用 `$DSH_HOME` 下的**若干个文本文件**拼出 **DSH 系统提示人设**（persona）的插件
（Runtime-Persona Soul loader），带**设置页可视化编辑器**。

DSH 原生只把 `AGENTS.md` / `CLAUDE.md` 当作「工作区指令」（以 user 角色提醒注入）。
本插件补上缺失的一块：**让人设成为真正的系统提示**——模型的身份与对话风格，
而不是一段上下文指令。

## 特性

- **系统提示注入**：人设通过 `systemPrompt.section()` 注册（`soul-persona` = persona 后缀 + 1）；
  账本快照则走 `systemPrompt.context()` 注册为**有序动态 runtime context**，由宿主渲染成一条
  user 角色的快照消息追加在对话尾部。理由只有一个：上下文缓存按**整段前缀的字节哈希**命中，
  系统提示词里只要有一个字节每次都在变，整段前缀就作废。把账本放进 section（哪怕排在最后）
  仍然会每次重刷整个前缀；放进动态 context 后系统提示词恒定，前缀一路命中，
  每次新增的只有尾部那几十字节。宿主只在文本真的变了时才追加这条快照。
- **多文件拼接**：`files` 是**有序数组**，按顺序拼成一段人设；先写身份、再写口吻、最后写禁忌，
  顺序由你控制（设置页可上下移动）。
- **设置页可视化编辑**：设置 →「角色人设」标签页里可以直接增删文件、调顺序、编辑正文、
  调分隔符 / 字节上限 / 总开关，并查看**合成预览**。
- **热更新**：每次组装系统提示都重新读取文件，改完**无需重启**，下一条消息即生效。
- **安全兜底**：文件缺失 / 为空 / 超过大小上限时自动跳过，不影响其它提示片段。
  `maxBytes` 同时是**总预算**，逐文件累加，超了就截断并停止。
- **字面渲染**：section 声明 `interpolate: false`，人设里的 `{{variable}}` 原样输出，不会被系统提示渲染器当成严格模板变量（那一类未知引用会抛错）。
- **只碰文本**：读写白名单只有 `.md` / `.markdown` / `.txt`，且拒绝一切越出 `$DSH_HOME` 的路径。
- **首装即有东西可写**：插件第一次运行会自动建出空的 `SOUL.md` 和 `rp-soul/parts/角色档案.md`
  （0 字节，你写什么就是什么），并把它们写进清单——设置页一打开就能看到文件、点开就能编辑，
  不用先手动建文件。**已存在的文件绝不会被覆盖**。
- **引擎（可选）**：结构化字段单独放在 `rp-soul/persona.md`（设置页表单可改），
  只有**你和她两个人**，引擎据此维护**她的情绪（心情条）/ 她对你的关系（信任·张力·阶段）/ 她的自主行动**三本账，
  外加**她的记忆**（ABM / SCM / CLPA 三层加一份落盘的日记，以 RimTalk-ExpandMemory 为底改的），
  由 SQLite 记账、可存档可回滚。人设散文仍原样进系统提示（恒定不变），引擎状态以一段 brief
  作为动态 runtime context 追加在对话尾部（每次只有它那几十字节在变）。
  **首次提示装配就读取账本**：通过 DSH 的异步 `system-prompt/assemble` 钩子等待侧车返回，
  重启后直接恢复已保存的局；人设有效且还没有局时自动开局。之后每次装配都重新读取当前状态，
  不依赖模型先调用 `soul_state` 来填充缓存。按会话模式只注入当前会话的账本。
- **唤醒线（可选）**：她按自己的时间醒来——她的安排、你们的约定、她自己的事、
  你久不说话、作息换段都可以是理由；到点往指定会话 steer 一条【我的时间】消息，
  她在那个时段里过自己的时间、用 `plan_next` 说好下一步，那一次结束再算下一次。
  次数与 token 双额度、安静时段、失败退避都在插件侧（引擎只算「什么时候、为什么」，是纯函数）。
- **乱码拒收**：文件名里出现 `U+FFFD`（说明送来的字节不是合法 UTF-8，典型是客户端按 GBK 编码发中文名）
  直接 400，不允许在磁盘上留下乱码文件名。

## 工作原理

每次组装系统提示时，插件调用一个 provider 函数，实时读取 `files` 里列出的每个文件
（相对 `$DSH_HOME`，默认 `C:\Users\<你>\.dsh\`，位置由 `$DSH_HOME` 决定），
按数组顺序拼接（中间插 `separator`，可选每段加 `<!-- soul-part: 文件名 -->` 注释），
把结果注册为名为 `soul-persona` 的提示片段。使用自定义段名，因此**不与** DSH 自带的
`deployment:persona-prefix` 冲突，可以在全局（profile 层）挂载。

配置有两层：

1. `cordis.patch.yml` 里的 `config` —— **首次运行的种子**；
2. `$DSH_HOME/rp-soul/config.json` —— 设置页保存后写这里，**此后以它为准**。

之所以不直接用 `settings.mutate` 写 `cordis.patch.yml`，是因为那条路要求把 Config 字段
声明成 `volatile`、并且靠 patch 热替换才生效，链路长；本插件的卖点是「改完下一条消息就生效」，
所以自己存一份 JSON，读的时候实时合并。

## 首次运行的种子文件

插件加载时（`apply()` 内，早于任何一次提示组装）会做一次幂等的落地检查：

1. 按 `files`（未配则 `fileName`，再退到 `SOUL.md`）逐项确认存在，缺哪个就 `writeAtomic(abs, "")` 建一个**空文件**（临时文件 + `rename` 原子落地）；
2. 总会额外补一份 `rp-soul/parts/角色档案.md`（同样只在缺失时建空文件）；
3. 存储配置 `rp-soul/config.json` 不存在时，写一份包含上述全部种子的 `files` 清单；
   已存在则**只在角色档案是新建成**的情况下把它追加到末尾（老用户升级路径），不动你已有的顺序。

这三步都只在**缺失**时动作，写完就走，因此重复启动不会改动任何内容。
磁盘只读 / 权限不足时整段包在 `try/catch` 里静默跳过——人设仍按已有文件生效，不会因为建不出种子而挂掉。

## 内部模块划分

插件按两部分组织：角色预设拼接，以及人设引擎。引擎内部的四个职责保持正常运行，
自主唤醒沿用原有 `wakeEnabled` 开关和设置页。模块划分用于让代码容易维护和替换实现。

| 模块入口 | 职责 |
|---|---|
| `engine/rp_soul_engine/modules/mood.py` | 想法结算、情绪表达校验、心情上下文 |
| `engine/rp_soul_engine/modules/memory.py` | ABM 收进 SCM、日记、采集、回忆与记忆上下文 |
| `engine/rp_soul_engine/modules/agency.py` | 下一步行动建议 |
| `engine/rp_soul_engine/modules/wake.py` | 个人安排的上下文；实际定时和送达由 `lib/wake.js` 执行 |

`modules/__init__.py` 是固定注册表，统一安排结算、提交前校验、提交后采集和上下文输出。
`domain/` 保留纯领域计算，模块不自行开事务或数据库。角色身份、时间、事实、关系、事件、
玩家授权、revision、撤销、存档及提交审计仍由统一内核维护，继续使用一个 Python 侧车和 SQLite。
替换某项实现时修改注册表对应项，并保持该项的阶段接口即可。

## 设置页

设置 →「角色人设」：顶部七个页签，**人设提示词 / 引擎人设 / 情绪 / 记忆 / 常识库 / 自主行动记录 / 唤醒**。
页签只影响界面，不影响数据——除「常识库」和「唤醒」，其余读的都是同一份引擎状态，
切换时各自取一次当前这一局；「常识库」是全局的一份表，换哪一局都一样；
「唤醒」页读的是插件自己的唤醒配置与定时器状态（和时间有关，跟账本无关）。

### 人设提示词

- **拼接顺序**：文件清单就是拼接顺序，用 `↑` `↓` 调整，`×` 从清单移除（**不删文件**）。
- **从库中添加**：下拉里列出 `$DSH_HOME` 下最多两层的所有 `.md` / `.txt`。
- **新建**：建在 `rp-soul/parts/` 下，自动加进清单末尾。
- **编辑器**：`Ctrl/⌘+S` 保存；切文件前若未保存会提示。
  打开标签页时会**自动选中第一个真实存在的文件**（清单里若全是缺失文件则选第一个），
  避免右侧一开始是「未选择文件」让人以为功能没生效。
- **空文件**：编辑器显示占位提示「这个文件还是空的 —— 直接在这里写」，直接写、保存即可。
- **引擎（账本）**：Python 侧车是否就绪（版本 / 数据目录）、当前人设包的结构摘要、
  真引擎校验人设（`/engine/persona`，失败时逐条列出 `路径：原因 —— 怎么改`）、标识（标题 / persona_id）。
- **高级**：总开关、每段 `soul-part` 注释、总字节上限、分隔符、合成预览。

### 引擎人设

`rp-soul/persona.md` 的表单版：id / 标题 / 心情基准 / 心情阈值，她的名字、称呼、年龄、性别、
开局态度、身份、外貌、表里两层语态，以及一张**作息表**（从几点到几点、在做什么）。
旧格式（带 `places` / `cast` 的多角色文件）会按第一个主要角色读成单人表单并标出来，点保存就写成新格式。
改完点保存写回文件，点「看 YAML」看原文，「校验」直接把这份人设交给引擎校验。
没有任何人填的「当前目标 / 处境」——那些由引擎按心情、关系、到期的事现场测算。

### 情绪

每次重算的**心情条**（RimWorld 式：基准 + 一组带衰减的 thought，夹在 0..100）：

读取状态和情绪面板时会预览真实时间流逝后的心情，不会提前写账；下一次提交先结算这段时间，
再确定这一次的行为档位。过期的负面想法不会继续限制她，离屏片段、事件结算和撤销仍在提交时处理。
自主唤醒后的缺席状态随账本保存，读取预览不会把你当成回来了；正常对话提交后恢复在场，同一分钟内也会更新。
时钟按整分钟结算，`real_at` 只推进已经结算的分钟，余秒留给后续累加；
连续两次 30 秒的对话会累计成一分钟。最近一次玩家发言仍记录实际时刻，不使用这个结算锚点。

- 她一张卡：`当前值 / 100 · 档位`、条形图、三档阈值（人设 `mood_thresholds` 可调，
  默认 `开心 ≥ 75` / `低落 < 45` / `难过 < 25`）、对你 的信任 · 张力 · 阶段 · 是否可自主行动。
- 下面按条列 thought：`delta`、标签、`记忆|情境`、还剩多少分钟。
- 每条右侧 `×` 手动删掉（会留一条审计记录，之后引擎不再复述这件事）；
  卡片底部「手动删除记录」列出这些审计条目。
- 情绪**不是**存档里的一份独立数值：`state.characters[npc].mood` 只存 thought 列表，
  值每次都从它重算，玩家侧不入库。

### 记忆

RimTalk-ExpandMemory 工作台的简化版：

- 下面是「ABM / SCM / CLPA」的纵向时间轴，按天分组（今天 / 昨天 / N 天前），
  卡片越淡说明她记得越模糊（透明度 = 活跃度）；可以按层过滤，按钮上写着每层的数量 / 容量。
- 点一条看详情、就地改：内容、重要度、活跃度（改了就从这个值重新开始衰减）、关键词、备注、Pin；
  也可以删掉（留一条审计记录）。你改过的记忆在挑选时会被优先想起。
- 「立即汇总」「立即写日记」：不用等 ABM 满 20 条 / 等到 23:30，下一次提交就先把它们写掉。
  页面上会提示下一次提交要交什么。

### 常识库

一张**全局共享**的表（不挂在任何一局上，换会话照样在）：每行是「关键词 + 权重 + 一条常识」。

- 一行长这样：关键词 `ds, deepseek`、权重 `0.8`、常识「deepseek 是深度求索旗下的大语言模型」。
- **只在被提到时才进上下文**：这句话里出现某个关键词，那条常识才被带进去；没提到的完全不占地方。
  中文按子串比，英文和数字按词边界比——所以 `ds` 不会在 `hands` 里误命中。
- 一句话命中好几条时按权重从高到低取，取几条在这里调（2~4 条，默认 4）。
  注入的样子是 `## 常识` 下面一行一条 `- ds： deepseek 是深度求索旗下的大语言模型`。
- 可以在这里加、改、删；她总结 SCM 和写日记时也可能顺手记下新的（同一组关键词会覆盖旧的那条）。

### 自主行动记录

按时间倒序的对话流水，可切「最近 10 / 20 / 50 次」：

- 每条：`第 N 次` + 行动模式（你说的话成了事实 / 你在尝试 / 其实…… / 你没说没做 / 时间在走）、
  时间、这次摘要、「停在这里」的 `open_action`。
- 分组列出这次实际发生的变化：`自主行动`（她的 kind + 动作文本 + 是否重大）、
  `离屏片段`、`对方的回应`（拒绝 / 协商 / 半配合 / 表面配合 / 真心回应 + note）、
  `关系变化`（信任 / 张力 / 阶段，阶段显示中文名）、`留下的情绪`。
- 顶部汇总：当前第几次 / revision / 共多少条记录 / 多少次自主行动 / 多少个离屏片段 / 时钟。
- 撤销过的记录（`undone`）与「开局」这类非 commit 记录也会出现，标出来但不重复算变化。

### 唤醒

让她**按自己的时间醒来**：到点了她自己过一段，可能顺手给你留一句话。
这一页只管「什么时候叫、叫几次、醒在哪」，具体她做什么由引擎的账本决定。

- **总开关**：关着就不会自己醒（默认关）；随时可以点「现在叫醒一次」手动叫。
- **她醒在哪场对话里**：下拉列出最近更新的会话（桌面宿主才有列表，命令行下为空）。
  选定后就往那一场 `agent.steer` 一条【我的时间】消息，她在那个时段里过自己的时间。
- **每天最多叫醒（次）** 与 **每天最多用掉（token）**：两道额度，0 = 不限。
  次数用完了当天就不再叫；token 按她醒来那几次的实际 usage 累加。
- **多久没说话算「想你了」（小时）**：你安静太久她会自己醒；没回话时从上次成功送达继续等下一段间隔（默认 6 → 12 → 24 小时，之后每次等 24 小时）。你在指定会话回复后重新从第一段等待。
- **安静时段**：默认 `00:00-08:00`。这段时间里只有**她自己写下的安排**能叫醒她，
  别的候选一律推到安静时段结束。
- **作息换段也叫我**：按她人设里的作息表，到换段的点醒一次（比如该「下班」了）。
- **状态**：下次唤醒时刻 + 理由（她说好做到的时间 / 你们的约定 / 她自己的事 / 想你了 / 作息换段）、
  今天已唤醒几次与用掉多少 token、上次没叫成的原因。

定时器与状态存在 `rp-soul/wake.json`（重启后自动重挂）；每次最多睡 5 分钟就对一次墙钟，
电脑睡眠或改时间都不会漏响；送达失败按 1/5/15/30/60 分钟退避。
会话正在跑、或你 15 分钟内刚说过话，就推后 5 分钟再试——不打断你们。
唤醒消息用第一人称，措辞模板可以放 `rp-soul/wake.md` 覆盖。

她醒来的那一次**没和你在一起**（`together: false`）：她不能替你做决定、不能编你们之间的约定，
`add_fact` 只能写她自己的事或内心；这一次本身就是她的时间，所以不要求离屏片段。

## HTTP 接口

宿主侧注册了 `/rp-soul` 前缀路由（`ctx.webServer.register({kind:'prefix'})`），
所有请求先过 `connection.requestRejection()` 信任栅栏（缺 `connection` 服务时 503 fail closed）：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/rp-soul/state` | 快照：配置 + 各文件元信息 + 库列表 + 合成预览 |
| GET | `/rp-soul/file?rel=...` | 读单个文件 |
| PUT | `/rp-soul/file` | 写单个文件 `{rel, text}` |
| POST | `/rp-soul/new` | 新建文件 `{name, text}` |
| GET | `/rp-soul/config` | 读生效配置 |
| POST | `/rp-soul/config` | 写配置 `{files, separator, annotate, enabled, maxBytes}` |
| GET | `/rp-soul/engine` | 引擎健康 + 人设摘要 + 当前这一局 |
| GET | `/rp-soul/engine/persona` | 用真引擎校验人设，返回结构摘要或带 path 的错误 |
| GET | `/rp-soul/engine/session?session_id=` | 读该局上下文（`depth=brief|full`） |
| GET | `/rp-soul/engine/mood?session_id=&npc_id=` | 她的心情面板（值 / 档位 / 阈值 / 条目 / 审计） |
| GET | `/rp-soul/engine/moods?session_id=` | 「情绪」页：她的心情面板 + 阈值 + 删除审计 |
| GET | `/rp-soul/engine/activity?session_id=&limit=` | 「自主行动记录」页：最近 N 次（1–50，默认 20） |
| GET | `/rp-soul/engine/memories?session_id=` | 「记忆」页：各层记忆、待交的总结 / 日记、删除审计 |
| PUT | `/rp-soul/engine/memory` | 改一条记忆 `{session_id, memory_id, revision, content?, importance?, activity?, keywords?, note?, pinned?}` |
| DELETE | `/rp-soul/engine/memory` | 删一条记忆 `{session_id, memory_id, revision, reason}`（留审计） |
| POST | `/rp-soul/engine/memory/request` | 立即汇总 / 写日记 `{session_id, revision, kind: fold|diary}` |
| GET | `/rp-soul/engine/common` | 「常识库」页：全部条目 + 每次注入几条 |
| POST | `/rp-soul/engine/common` | 加一条 `{key, weight, content}` |
| PUT | `/rp-soul/engine/common` | 改一条 `{common_id, key?, weight?, content?}` |
| DELETE | `/rp-soul/engine/common` | 删一条 `{common_id}` |
| PUT | `/rp-soul/engine/common/limit` | 每次注入几条 `{limit: 2..4}` |
| DELETE | `/rp-soul/engine/thought` | 手动删一条情绪 `{session_id, npc_id, thought_id, revision, reason}` |
| GET | `/rp-soul/wake` | 「唤醒」页：配置 + 定时器状态 + 可指定的会话清单 |
| POST | `/rp-soul/wake` | 改唤醒配置（字段同上表 `配置` 一节） |
| POST | `/rp-soul/wake/now` | 现在叫醒一次（绕过时刻与安静时段，照样计额度） |

状态码：400 = 参数不合法（扩展名不在白名单 / 路径穿越 / 含 `U+FFFD` 的乱码名）、
413 = 请求体超 1 MiB、503 = 缺 `connection` 服务时 fail closed、401/403 = 信任栅栏拦下。

## 引擎（可选）

人设散文解决「他是什么人」，引擎解决「他现在怎么样、会怎么变」。引擎是随插件分发的
Python 包（无第三方依赖，`python -m rp_soul_engine` 常驻子进程，stdio JSON-lines 通信），
需要 **Python ≥ 3.10**；找不到 Python 时插件照常工作，只是三个工具会明确报未就绪。

### 引擎人设：单独一个文件

引擎要的结构化字段（她是谁、作息、心情阈值……）放在 **`$DSH_HOME/rp-soul/persona.md`**，
就是一个纯 YAML 文件（不需要 `---` 包裹，写了也只当装饰）。它和人设提示词是两件事：

- 人设提示词（`files` 里那些 md）只管「他是谁、怎么说话」，会被原样注入 system prompt；
- `persona.md` 只管引擎要的数据，**不注入提示词**。

设置页「角色人设 → 引擎人设」里是表单，不用手写 YAML；想看一眼原文就点「看 YAML」。
**改完就生效**：`persona.md` 是静态事实，引擎每次 `soul_state` / `soul_commit` 都会把它
一并送过去，所以名字、称呼、年龄、外貌、语态、作息、心情基准当场就跟上，不用为了看一眼新的
名字重开一局。剧情那半不动：时间、你们之间的关系进度、心情里已经发生的想法、
记下的事实都留在原地。唯一有条件的字段是 `start_stage`——它只描述「开局时这段关系在哪」，
所以只有当两边还干干净净（信任 0、张力 0、没有历史）时才按文件来；一旦有过往来，
关系进度就是账本说了算，文件改不动它。

这份文件不存在时退回老行为：从**第一个**带 YAML 前置块的散文文件里读（表单会提示「从散文前置块迁移」，
点一次保存就搬过来，之后散文里的前置块不再参与解析）。

```yaml
id: lin_wan
title: 雨夜诊所
name: 林晚
role: 夜班医生
age: 34
gender: female
voices: {surface: 说话克制。, inner: 一直在等一句道歉。}
start_stage: familiar
mood_base: 55
mood_thresholds: {open: 72, closed: 40, break: 18}
routine:
  - {from: 540, to: 1080, doing: 在诊所上班}
  - {from: 1380, to: 420, doing: 睡觉}
```

只有一个人，所以是平铺的：`id`（ASCII 小写，既是人设 id 也是她的 id）/ `name` / `age` / `gender` /
`voices.surface` / `voices.inner` 必填；`title` 不写就用名字；`adult_context`、`appearance`、`call`、`role`
可选，不写就不写，引擎不会替你编。没有地点，也没有登场退场：「在场」就是你们在说话。
`routine` 是**作息**：一天里某段时间她通常在做什么。表单上按「几点到几点」填（可跨午夜，如
22:00 到 06:00），存进文件仍是分钟数 0–1439 —— 那是引擎内部的单位，你不用管。引擎拿它回答
「你不在的时候她在干嘛」——上下文里会给出 `routine_now`，说明她此刻按作息在做什么。
**旧格式照样能读**：带 `places` + `cast` 的多角色文件，按第一个 `tier: major` 的角色读成她，
她的 `schedule` 换成作息「在<地点名>」，其他角色和地点不再参与。
`start_stage` 是**开局时她对你的关系阶段**，不填就是 `stranger`（陌生）；可选
`stranger` / `acquainted` / `familiar` / `flirting` / `testing` / `intimate` / `committed`。
**没有 `goal` / `decision` / `situation` 这几项**：他现在想做什么、心里压着什么，由引擎按心情、
关系、到期的事现场测算，人写一份静态的反而会每次盖住活的信号。性格与说话方式写进人设提示词就够了。
没有 `persona.md`、散文里也没有前置块时，正文首行当标题，但**不发明角色**——
名字、年龄这些缺了就是缺了，自动开局与 `soul_admin start` 都会拒绝，并说明缺什么。

### 作用域：全局还是按会话

默认 `engineScope: global`——**所有 DSH 会话共用同一局**。心情、人际关系、未结的事
是「她这个人的」，不是「某个窗口的」：在 A 会话里吵完架，切到 B 会话她还带着那股气。
从 `session` 改成 `global` 时，映射表里最近活跃的那一局会被自动**接管**成全局局
（`adopted_from` 记着来历），不会重开一局把账本扔掉。
需要「每个会话各自一局」时把 `engineScope` 设成 `session`（设置页引擎卡上有切换按钮）。

全局作用域下开局是**自动的**：`soul_state` 发现没有局会就地开一局（返回 `autoStarted: true`），
不需要先跑 `soul_admin start`。开不起来（人设缺名字、年龄等）不算失败，工具会如实说
「这一次只按人设散文演，不要假装有账本」。

### 时间：按真实墙钟，不是虚拟时钟

引擎没有「游戏时间」这个概念，也没有 `advance_time` 这种操作：**每一次的时间跨度就是真实的
时间间隔**——上一次结算的时刻记为 `real_at`，这一次提交时取当前时间，两者之差就是要结算的
跨度。你隔三分钟回来，它就是三分钟；隔一夜回来，它就是一夜，事件到期、心情衰减、场景切换
都按这个真实跨度一次性补算。

- 时钟按真实分钟数累加：`day` / `minute` 是「建局那一刻」加上这段时间走过的分钟推出来的，
  所以同一天内不变，跨过零点自然 `day + 1`，隔了几天回来也落在正确的那一天。
- 跨度 ≥ 60 分钟（或跨天）判定为 `full` 档：这一次必须先补一条 `offscreen_beat`，
  说明你不在的这段时间她做了什么（引擎附上她这段时间的作息作参考）；≥ 16 分钟为 `brief`，
  可以写也可以不写；再短就是 `routine`，你们一直在说话，不算分开。
- 时间**先结算、再应用这次的操作**：分开的那段时间发生在这之前，所以离屏片段描述的是它，
  这次新记的情绪和约定从「现在」开始算，不会被刚过去的那段时间立刻消磨掉。
- 模型不能快进、也不能自己写时间：`soul_state` 不再接受快进参数，`new-game` 不再有
  `start_minute`，`persona.md` 里也不再需要 `start` 字段。
- 时钟只在真实时间向前时前进；同一时刻重复提交不会让时间倒流。

### 三个工具

| 工具 | 什么时候用 |
|---|---|
| `soul_state` | 读这局的工作指令：`agency`、`due_soon`、`known_facts`、`her_knows`、要不要交总结。心情、记忆、常识、时间、在场、该交的总结「当前局面」每轮都已写进上下文，这里不再重复一遍。不是每轮都必调——快照里没有的（比如 `agency` 候选）才需要读。`want_twist` 取转折 |
| `soul_commit` | 写完这一次后提交。`operations` 是账本改动清单（`npc_response` / `npc_action` / `relationship` / `add_thought` / `add_fact` / `offscreen_beat` …，最多 40 条）。只有你们两个人，所以 op 里不写是谁；事实用 `scope` 说清谁知道（`shared` 你们都知道 / `player_only` 只有你知道 / `companion_only` 只有她知道 / `inner` 她心里的）。可选的 `remember` 用第一人称写她会怎么记得这一次；引擎要把 ABM 收进 SCM / 写日记时，这次提交带上 `memory_fold` / `memory_diary`（汇总时可加 `memory_keep` 挑 0~2 条进 CLPA）。引擎校验后要么全收要么全驳（驳回带 `path` 与原因，最多重试 2 次）。**时间不用写**：引擎按真实时钟自己结算这次过了多久 |
| `soul_admin` | 开局（`start`，全局作用域下通常不必手动开）/ 回滚（`undo`）/ 存档（`save` `load` `delete` `list`）/ 改边界与偏好（`set_safety` `set_preferences`） |

### 记忆（以 RimTalk-ExpandMemory 为主）

她的记忆像人一样按「时间远近 + 还记不记得」流转，而不是按项目 / 主题建条目。三层加一份落盘的日记：

| 层 | 每小时衰减 | 容量 | 怎么走 |
|---|---|---|---|
| ABM | 不衰减 | 20 | 这段对话里的原话。**不进上下文**（对话本身已经在里面了）。满 20 条或搁置一小时，由宿主起的子代理收成一条 SCM，ABM 清空 |
| SCM | 0.005 | 50 | 跨对话的情景记忆，记着「多久以前」；约一个月淡掉，满了淘汰最不活跃的。**只有它会被想起来**（每次 3~5 条） |
| CLPA | 不衰减 | 不限 | 她自己挑出来要一直记着的（汇总时挑 0~2 条 + 里程碑自动进），只有你手动才删改 |
| 日记 | — | — | 每晚 23:30 由模型把当天 SCM 写成一篇，落盘成 `journal/<session_id>/diary-<日>.md`；不删 SCM，设置页不展示 |

- **怎么记下来**：每次自动记一条，不花额外的模型调用。有 `remember` 就用她自己的话，没有就用摘要；
  你说的话和她的原话一起留着。离屏片段 / 她一个人的那几次记成「经历」。
- **记得多牢**：重要度 = 0.3 + 这次情绪起伏（新增情绪的 |delta| 之和 / 30，最多 0.5）+ 里程碑 0.2；
  关系阶段前进、第一次立下你们之间的约定会**自动 Pin**（不衰减、不清理）。活跃度低于 0.025 且没 Pin 就被忘掉。
- **不许凭空造物**：写进记忆的文字（`remember`，以及没填 `remember` 时退回用的 `summary`）只许用这次正文里
  真出现过的人、物、动作和你亲口说过的话——不得新增上下文没提到的道具、不得编造对方没做过的动作、
  不得补写正文没发生的场景。提示词里对 `remember` / `summary` / `operations` 三处都写了这条约束，宁可写得短。
- **ABM 不靠模型交账**：每一轮结束时宿主自己把「你说了什么、她回了什么」写成一条 ABM（`你：… 她：…`），
  模型忘了调 `soul_commit` 也照记不误；模型这一轮交过账就跳过，不重复记。这是 RimTalk 的做法：记忆来自被拦下的
  那次互动，而不是模型恰好愿意写。自动记的条目不推进时钟，也不替代交账。
- **ABM 收进 SCM**：ABM 满 20 条，或者搁置一小时以上（说话时上游那批已经过去一小时），
  宿主自己起一个子代理，把这一批收成一条第一人称的 SCM（≤300 字）、ABM 清空，
  顺手挑 0~2 条写进 CLPA。整个过程不经过对话里的模型——它不调 `soul_commit` 也照收。
  子代理用 `fork`：它带着这一局已经走完的上下文开工，知道「他们」是谁；结果是回给宿主
  而不是回到对话里（`delivery: "caller"`），abort 也是自己建的，不跟着回合一起被掐。
  没有子代理服务时退回老办法：让模型在下一次交账时写。
- **日记**：每晚 23:30 有一次专门为日记的唤醒；引擎给出当天还没写过的 SCM，
  由模型写成一篇（≤300 字），落盘成 `journal/<session_id>/diary-<日>.md`，不同账本各自保存。23:30 那会儿没人在也会补上前一天；
  被推后跨过午夜照样补，只是不再等到下一个 23:30。
- **想起来**：每次上下文的 `memories` 只从 SCM / CLPA 里按 RimTalk 的打分取（brief 3 条 / full 5 条，
  低于 0.15 不要）：时间远近 + 重要度 + 和线索的重合 + 层级 + Pin / 你改过 + 活跃度。
  每行写成 `[记得多清楚] 正文（周几 + 钟点）`：活跃度 0.7 以上「记忆犹新」、0.4 以上「大概记得」、
  0.1 以上「有些模糊了」，再淡就是「记不起来了」（低于 0.025 会被删掉）。线索是你这句话
  （装配时从会话里取最后一条你说的，不需要模型自己调工具）、
  她作息上此刻在做什么、快到期的约定、她心里压着的事。你在 = 社交场景（往事也容易被勾起，30 天窗口），她一个人 = 普通场景（只看最近）。
- **越想越牢**：被你这句话勾起来的记忆，活跃度回升 0.1、重新开始衰减——常被提起的事不容易淡掉（借自 MemoryBank）。
- **她知道的事**：上下文的 `her_knows` 给出最多 5 条只有她知道的事（她的秘密、表面配合时的真实打算），按线索优先。
- 注入时的时间是「周二晚上 21:40」：周几 + 钟点，钟点精确到分钟。日期（几月几号）
  条目里本来就存着，设置页按日期分组显示，注入时不再重复念一遍。

### 心情条（情绪怎么算）

`mood = clamp(mood_base + Σ thoughts, 0, 100)`。每条 thought 是
`{label(≤20字), delta(-30..+15), kind, source_fact_id, since_turn, expires_at, decay}`
——**引擎自己算情境类**（在你身边 / 你不在 / 隔了一天以上才回来 / 事件到期 / 张力高 / 深夜打扰；
带时限的那几条——比如「很久没见你」挂一天——起因过去了也会挂到时限再消失），
模型只能通过 `add_thought` 加记忆类，且必须挂到一个事实 id 上（不能凭空扣心情）。
引擎自己写的记忆类只来自**你对她做了什么**：信任变化（×3）、关系阶段前进、事情搞砸。
**她自己选的回应（拒绝 / 配合）不进她自己的心情**——否则「低落 → 只能冷回应 → 更低落」会一路滑进崩溃档。
衰减两种：`linear`（默认，随时间等比缩小，`|delta| < 1` 才删）与 `none`（到点一刀切）。
同一角色最多 20 条（12 记忆 + 8 情境），超了按「原始强度」淘汰最弱的。

档位只做**行为门禁**，不产生精神状态。档位按**真实时间结算后、这次操作开始前**的心情判定，
与 `soul_state` 的时间预览一致；这次中途加减想法不改变这次的门禁：

| 档位 | 区间（默认） | 影响 |
|---|---|---|
| `open` | ≥ 75 | 允许关系阶段前进；`npc_action` 的 `significant` 冷却缩到 10 分钟 |
| `normal` | 45–75 | 无额外约束 |
| `closed` | 25–45 | 驳回 `stage_advance`；回应（`note`）≤30 字，也可以真诚回应或用轻微行动表达感受 |
| `break` | < 25 | 驳回 `stage_advance`；回应（`note`）≤30 字。这次有简短回应或一种情绪表达即可，不要求重大行动；重大情绪表达不受冷却限制 |

低心情的 `npc_action.kind` 新增四种表达，仍保留 `provoke` / `leave`：

| kind | 表达 |
|---|---|
| `silence` | 沉默，暂时没有开口 |
| `seek_comfort` | 寻求安慰，希望有人陪一会儿 |
| `change_topic` | 暂时放下这个话题，换件事说 |
| `withdraw` | 想自己待一会儿，慢慢缓过来 |

轻微表达用 `significant: false`。这些行动可以作为对玩家尝试的反应，但本身不表示同意亲密，
也不会自动推进关系或增加心情。候选按当前想法和关系给出理由（信任较高时更倾向寻求安慰），
具体反应与措辞由模型结合人设选择，低心情不自动等于敌意，也不用立刻变开心。

非崩溃档下，`significant: true` 的 `npc_action` 必须写 `kind`，且只能取这次开始时引擎给出的
agency 候选里的种类（`soul_state` 的 `agency`）；不重大的行动不受此限。

阈值可在 `persona.md` 的 `mood_thresholds` 里改（必须满足 `0 ≤ break < closed < open ≤ 100`，
不满足**报错而不回退默认**）。玩家自己的心情**不入库**——只记录她怎么想。

### 心情与关系是两条轴

mood 是「此刻怎么样」（短期会回落），trust / stage 是「长期怎么判断你」（慢变 7 级）。
信任高 + 心情低时可以寻求安慰，也可以想独处；信任低 + 心情高时仍可能对你保持距离。
`relationship` 的 `trust` 一次最多变动 2，阶段前进要求这次有玩家实际行动 + 她同时
`partial`/`genuine` 回应，否则报 `INVARIANT_VIOLATION` 而不是自动截断。

## 与 `AGENTS.md` 的区别

| | `AGENTS.md`（原生） | `SOUL.md`（本插件） |
|---|---|---|
| 注入形式 | user 角色 `<system-reminder>` | **系统提示片段** |
| 语义 | 工作区指令 / 指导 | 身份与对话风格（人设） |
| 覆盖 | 不覆盖系统提示 | 直接参与系统提示渲染 |

## 注意事项

- **`complete: true` 的预设不会生效**：例如内置 `minimal` 预设把 persona 作为
  唯一系统提示，会丢弃所有其它片段（包括本插件的注入）。请改用 `standard` 等
  普通预设，或自行新建预设：
  ```yaml
  agent-presets:
    default: standard
  ```
- 若你同时把 SOUL 内容合并进了 `AGENTS.md`，建议删掉那份，避免人设注入两次。
- **旧存档自动升级**：多角色时代的存档（state schema 1）在引擎第一次启动时迁移成单人格式，
  迁移前先在数据目录的 `backups/` 里备份一份数据库，迁移失败会自动还原。规则和旧人设文件一样：
  第一个主要角色是她，她的心情、她对你的关系、你们知道的事和约定都保留，其他角色、地点、
  NPC 之间的关系不再保留。旧版导出的存档文件导入时按同一套规则升级。
  记忆换成分层结构后（原 state schema 3 的那次迁移）同样自动迁移：原来的章节和前情进 CLPA，
  最近的摘要进 ABM / SCM；迁移过来的记忆从迁移那一刻开始淡去。
- **引擎每次至少一次 stdio 往返**（毫秒级）。引擎不可用时不会阻塞对话，只是
  `soul_state` / `soul_commit` / `soul_admin` 会返回「引擎未就绪」并说明原因
  （缺 Python / 版本太低 / 引擎包缺失），此时人设注入照常生效。
- **引擎要 3.10 以上**，且不加 `PYTHONPATH` 也能 import 的形态是「装完就带 `engine/` 目录」，
  所以请用 `dsh plugin add dsh-rp-soul` 安装，别手工拷 `lib/`。
- **人设改心情阈值不需要迁存档**：`revision` 是「散文 + 结构化字段」的 sha256，
  但引擎只在新开局时读阈值，已有存档沿用开局时那份。

## 验证 / 卸载

- **验证**：新开一个对话，观察系统提示开头出现 `SOUL.md` 的人设文本；修改
  `SOUL.md` 再发消息，随下一条请求更新。
- **验证引擎**：设置 →「角色人设」→ 引擎卡里应显示「就绪」与 Python 版本；
  让模型 `soul_admin start` 之后，同一张卡里能看到这一局与她的心情条。
  或直接命令行：`python -m rp_soul_engine <<< '{"id":"c1","command":"doctor"}'`
  （在 `engine/` 目录下），返回 `{"id":"c1","ok":true,...}` 即通。
- **卸载**：`dsh plugin remove dsh-rp-soul`（自动移除 bundle 挂载）；
  若曾手动安装，再从 `cordis.patch.yml` 删除 `soul-persona` 行并删除
  `profiles\plugins\soul-persona\` 目录。
