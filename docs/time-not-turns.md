# 去掉回合：用时间过日子

目标：她的日子按真实时间过，不按「聊了几句」过。玩法规则里不再出现「第几回合」「最近 N 回合」，
你和她（模型）也都看不到回合这个词。

一句话：**`turn` 留着当账本流水号，规则全部改读时间。**

---

## 0. 现状：时间这条线已经有一大半

| 已经按时间走的 | 在哪 |
|---|---|
| 两次说话之间隔了多久（真实墙钟，零头分钟会累计） | `state.real_at`、`state.real_span()` |
| 隔 ≥ 60 分钟就算新的一段相处（新场景） | `structure.SCENE_BREAK_MINUTES`、`settlement.new_scene` |
| 结算分档、心情按经过的小时变化 | `settlement.tier_for`、mood 的 settle 钩子 |
| 你上次说话的时刻 | `state.last_player_at`（只在 `player_input` 非空时更新，唤醒回合不刷新） |
| 「这几天」的记忆按小时衰减、唤醒按真实时间排 | `memories.DECAY`、`wake.py` |

还在按回合数算的，只有下面第 2 节这几条规则，外加界面和工具描述里的「回合」二字。

## 1. `turn` 降级为账本流水号（不删）

撤销、改写上一条、存档、幂等去重、事实日志、归档顺序都靠它定位「第几次提交」：

- `undo-turn` / `replaces_turn`、`undo_points`、`UNDO_KEEP=30`
- `turn_log`、`write_fact_changes`、`archive` 表、各种 `coord`
- `MAX_MEMORY_TURNS=40`（滚动日志条数）、`RECORD_MAX_TURNS=12`（一次补记最多几条）

这些是存储和一致性问题，和她的日子无关，**照旧按条数**。字段名 `turn` 不改（改名要动数据库列、
导出格式和几百处引用，换来零行为变化），只在 `state.py` 顶部注明：

```python
# turn 是账本流水号（第几次提交），只给撤销/存档/日志定位用。
# 任何玩法规则都不许读它：冷却、「最近」、刷新频率一律按时间算。
```

各处的 `since_turn`、`created_turn`、`resolved_turn`、`set_turn`、`history[].turn` 也是流水戳，保留；
需要给人看的地方改显示时间（见第 4 节）。

## 2. 规则换成时间

| 规则 | 现在 | 改成 | 存什么 |
|---|---|---|---|
| 重大自主行动的冷却 | `COOLDOWN_TURNS=3`（心情 open 时 2） | **20 分钟**（open 时 10 分钟） | `counters.major_action_at[npc]` = 游戏时钟 |
| 自主候选里「她刚知道的事」 | `agency.RECENT_TURNS=3` | **30 分钟内**知道的 | 事实加 `at`（游戏时钟） |
| 上下文里事实排序的「最近」加分 | `facts.RECENT_TURNS=5` | **60 分钟内**的 | 同上 |
| 定期给完整上下文 | `state.turn % 5 == 0` | 距上次完整上下文 **≥ 15 分钟** | `counters.full_context_at` |
| 「刚刚」这一层 | 最近 10 条 | **这一段相处里的**，仍最多 10 条（token 预算）；开新的一段时，旧的「刚刚」整体落进「今日」 | 不新增，用条目已有的 `at` 和 `scene.since` |
| `offscreen_beat_turn` | 只写不读 | 删掉 | — |

为什么是这些数：

- 平常聊天大约 1–3 分钟一来一回。原来 3 回合冷却就是 5–10 分钟，改 20 分钟是有意放慢：
  连续聊一小时，她最多主动做 3 件「重大」的事。不重大的随口举动不受冷却限制，和现在一样。
- 唤醒回合之间本来就隔半小时以上，冷却不会卡住她自己的时间。刷屏由唤醒线的每日次数管。
- 「最近」30 / 60 分钟：分别对应「刚说的事她会接着想」和「这一阵聊过的事更容易想起来」。
- 完整上下文 15 分钟一次，和原来每 5 回合的频率差不多。新的一段、跨天、要交总结、提交失败时照旧
  立刻给完整的，原规则保留。

时间一律用**游戏时钟**（和真实时间是同一条线），所以撤销会把冷却和「最近」一起退回去，不会错位。

`can_act` 的签名从 `(state, cid, turn, bonus)` 改为 `(state, cid, at, bonus)`；
`agency.candidates` 和 `simulation` 里传 `state["turn"] + 1` 的地方改传当前时钟。

## 3. 隔了一阵再回来：注入事实，不注入结论

上下文里新增一块「这段时间」（`since_last`），**只在距你上次说话 ≥ 16 分钟时出现**
（16 分钟就是现在可以写离屏片段的线）。

内容全部来自账本：

```
距你上次说话：3 小时 10 分（上次 21:10，现在 00:20）
这段时间里她：
  - 21:00 说好「去洗澡」做到 21:30（已过）
  - 22:15 给你留过一句话（你还没回）
  - 离屏片段：在阳台看了会儿书
按作息，现在是「睡觉」时段
```

- 来源：`last_player_at`；`last_player_at` 之后的 `plan` 和已兑现的安排；
  这之后 `together:false` 回合里的 approach 行动；这之后的离屏片段（「刚刚」/「今日」里的
  experience 和 action 条目）；作息当前段。
- **不写任何情绪词**（失落、想你、生气……）。情绪由心情系统按同样的事实算，模型照着心情演。
- 工具描述加一句：「隔得久不等于她一直在等你。她这段时间做了什么、现在心情怎样，以上面为准。」

这样隔三小时回来，她可能有点失落，可能已经睡了，也可能自己忙得挺开心，取决于这三个小时里
实际发生了什么。

`last_player_at` 的规则不变：只在你说话时更新，她被唤醒、自己说话不刷新，否则「想你了」永远不会触发。

## 4. 界面和工具里不再出现「回合」

| 地方 | 现在 | 改成 |
|---|---|---|
| 撤销回执 | 「已撤销第 N 回合」 | 「已撤销上一次（00:20 那条）」 |
| 存档默认名、存读档回执 | 「X-第N回合」 | 「X-第3天 00:20」（`clock_label`） |
| 冷却报错 | 「第 N 回合刚有过重大行动，第 M 回合起才能……」 | 「23:50 刚有过重大行动，00:10 之后才能再有；这次写成非重大行动」 |
| `replaces_turn`（模型要填回合号） | `replaces_turn: 12` | 工具层改成 `revise_last: true`，桥接层自动换成当前的 `replaces_turn`；引擎接口不变 |
| `soul_commit` 等工具描述（engine-bridge.js 约 27 处） | 「这一回合」「下一回合」 | 「这一次」「接下来」 |
| 设置页活动日志、存档列表（client.js 约 14 处） | 显示回合号 | 显示时间 |
| 唤醒文案、wake.js（约 6 处） | 「唤醒回合」 | 「她醒着的这一次」 |
| README（约 45 处） | — | 同步改写 |

命令名 `commit-turn` / `undo-turn` 是内部接口，不改，只改它们的描述文字。

## 5. 迁移（只往前，照现有 migrate.py 的方式，迁移前自动备份）

| 旧数据 | 处理 |
|---|---|
| `counters.major_action_turn` | 删掉，换成空的 `major_action_at`（最坏情况：升级后她马上可以有一次重大行动） |
| `counters.offscreen_beat_turn` | 删掉 |
| 事实没有 `at` | `turn ≥ state.turn - 5` 的（旧规则下算「最近」）填当前时钟，其余填 `None`（不算最近） |
| `counters.full_context_at` | 填 `None`，下一次提交给完整上下文 |
| 「刚刚」里不属于当前这一段的条目 | 第一次提交时按新规则自然落进「今日」，不需要迁移 |

## 6. 分阶段（每阶段测试全绿再往下）

1. **引擎规则 + 迁移**：第 2、3、5 节。Python 测试用显式时间：
   - 20 分钟内连发 30 条，只允许一次重大行动；第 21 分钟可以；open 心情 10 分钟。
   - 撤销后冷却跟着退回。
   - 事实 29 / 31 分钟的「最近」边界。
   - 「刚刚」跨过 60 分钟的间隔后落进「今日」，Pin 住的不动。
   - 「这段时间」：15 分钟不出现，16 分钟出现；内容里没有情绪词；唤醒回合不刷新 `last_player_at`。
   - 旧存档迁移后能正常提交、撤销。
2. **文字**：第 4 节。引擎回执和报错、桥接层工具描述和 `revise_last`、设置页、wake.js、README；
   加一条测试，扫一遍面向模型和界面的文本里没有「回合」。
3. **验证**：全量测试；再用假时钟跑一段脚本化的一天（白天连续聊、下午隔 3 小时、晚上唤醒两次、
   半夜聊过 0 点），人工看一遍注入的上下文。
