# 唤醒线方案

已定：额度按「次数 + token」；唤醒来源是她的安排、约定到期、想你了、作息换段（不做早上兜底）；
她醒来的那一次在指定会话说的话算「给你发消息」。

目标：你不在的时候，她也会到点自己醒来、做点什么、可能给你发一句话，而不是只在你发消息时才动。

范围：设置页指定一个会话 → 引擎算出下次该醒的时间 → 到点往那个会话里 steer 一条「我的时间」消息 →
她在那个时段里过自己的时间、用 `plan_next` 说好接下来做什么做到几点 → 那一次结束再算下一次。
每日额度兜住花费。参考了 dsh-world 的闹钟线（MIT），但下次什么时候醒不只由她自己定，引擎也会按账本叫醒她。

不在这次范围：`reach_out`（系统通知 / 桌宠推送）、每日回顾写日记、近期原文记忆。见文末「之后」。

---

## 1. 一次唤醒的样子

```
22:30  她在 soul_commit 里写 plan_next：去洗澡，做到 23:00
23:00  定时器到点 → 往指定会话 steer：
       【我的时间】23:00 了，这是我说好洗完澡的时间。接下来做什么由我决定……
       （这一次她不在你面前：together = false）
       她：读 soul_state → 写一段（可能给你发一句“洗完了，你睡了吗”）→ soul_commit
           → plan_next：看会儿书，做到 23:40
23:40  再醒一次……
```

指定的会话就是你们的聊天窗口：她醒来的那一次说的话算**给你发的消息**，你打开那个会话就能看到。
主动给你留言记一条 `npc_action(kind: approach)`：带 `significant` 时照常受候选和冷却约束
（你不在时的打分本来就偏「观察」，心情好、关系熟、有事要跟你说时才会出现 approach），
随口一句不重大的（「晚安」）不受限。你在那个会话里回她，这一次就变回「你们在一起」。

## 2. 引擎侧

### 2.1 每次提交多一个 `together`（默认 true）

| | together: true（你在） | together: false（她一个人） |
|---|---|---|
| 谁在场 | 你和她 | 只有她（情境情绪「你不在」） |
| `npc_response` / `acts_on_her` / `player_authorized` | 照常 | 驳回（你没在说话） |
| `add_fact` 的 scope | 四种都行 | 只能 `companion_only` / `inner` |
| `reveal_fact` 互通知识 | 照常 | 驳回：你不在场，不能直接变成双方都知道 |
| 你们之间的约定 | 照常（要你本人答应） | 不能新建、兑现或取消 |
| 离屏片段要求 | 隔 1 小时以上必须补 | 不要求：这一次本身就是她的时间 |
| 自主行动 | 候选照常 | 候选照常（不在场时的打分已经有：观察、主动找你……） |

`together` 不让模型自己填：桥接层知道这一次是不是她醒来起的（见 3.3），自动带上。

### 2.2 新 op：`plan_next`（她自己定的安排）

```json
{"op": "plan_next", "note": "去洗澡", "in_minutes": 30}
{"op": "plan_next", "note": "睡觉", "until": "07:30"}
```

- `in_minutes`（1–1440）或 `until`（HH:MM，下一个这个时刻）二选一。
- 记进账本 `state.plan = {note, until(时钟), set_turn}`，撤销能退回去；新的替换旧的。
- 你在场时也能用：「我去洗个澡，半小时后找你」就是一条 `plan_next`。
- 上下文里多一项 `companion.plan`：「她说好 去洗澡 做到 23:00」。

### 2.3 新命令：`next-wake`（只读）

引擎按账本算出所有候选，取最早的一个，返回真实时间（ISO）和理由：

| 候选 | 什么时候 | 唤醒消息里说的理由 |
|---|---|---|
| 她的安排 | `plan.until` | 「这是我说好做到的时间：去洗澡」 |
| 你们的约定快到了 | 约定到期前 30 分钟 | 「离『周末去看海』还有半小时」 |
| 她自己的事到期 | 到期时刻 | 「『交夜班报告』到时间了」 |
| 想你了 | 第一次从你上次说话起等 N 小时（默认 6）；之后从上次成功送达起等 12 / 24 小时，达到 24 后保持每次等 24 小时；你回复后重置 | 「{你} 已经 6 小时没说话了」 |
| 作息换段 | 作息下一段开始（可关） | 「到 18:00 了，按平常该『下班』了」 |

一个候选都没有（没安排、没约定、想你了关着、没写作息）就不叫，等下一次你们说话后再算。

- 游戏时钟和真实时间是同一条线（建局时刻 + 走过的分钟），所以「时钟 → 真实时间」直接换算。
- 安静时段里（默认 00:00–08:00）只有「她的安排」会叫醒她（她自己说了睡到 07:30 就 07:30 醒），
  其余候选推到安静时段结束。
- 唤醒消息里写清是哪一条候选，模型知道为什么醒；同一时刻有几条就一起说。
- 玩家暂停（safety.paused）时不唤醒。

## 3. 插件侧（新模块 `lib/wake.js`）

### 3.1 配置（设置页写进 `rp-soul/config.json`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `wakeEnabled` | false | 总开关；默认关，选好会话再开 |
| `wakeSessionId` | "" | 指定的会话 |
| `wakeDailyLimit` | 12 | 每天最多唤醒几次 |
| `wakeDailyTokens` | 300000 | 每天她醒来的那几次最多用多少 token（0 = 不限） |
| `wakeQuiet` | `00:00-08:00` | 安静时段 |
| `wakeMissYou` | 6 | 多少小时没说话算「想你了」（0 = 关） |
| `wakeRoutine` | true | 作息换段要不要叫醒她 |

### 3.2 定时器（照搬 dsh-world 的做法）

- 只有一个待响的唤醒；存在 `rp-soul/wake.json`（下次时间、理由、今天的次数和 token、连续没回的次数、最近的错误），
  重启后按它重新挂上。
- 每次最多睡 5 分钟就重新对一下墙钟：电脑睡眠、改时间都不会漏响。
- 送达失败按 1 / 5 / 15 / 30 / 60 分钟退避重试。
- 什么时候重算下一次：每次 `soul_commit` 成功后、她醒来的那一次结束后（`turn/end`）、改配置后、插件启动时。

### 3.3 到点之后

1. 检查：开着、会话还在、今天次数和 token 没超、不在安静时段（她的安排除外）、引擎就绪、没暂停。
   不满足就记一条原因，按规则改期（超额就推到明天）。
2. `sessionController.resolveAgent(会话)`；会话正在跑（你正在跟她说话）就推后 5 分钟——不打断你。
   你上次说话距今不到 15 分钟也推后：你们还在聊，用不着她「醒」。
3. `agent.steer(createUserMessage({source: {kind: "rp-soul-wake"}, content: [唤醒消息]}))`，然后 flush。
4. 记下「这个会话现在是她醒来的那一次」，直到 `turn/end`；中途你在那个会话里发了消息，就清掉这个标记（变回 together）。
5. 她醒来的那一次里每条 `assistant/message` 的 usage 累加进今天的 token。
6. 桥接层的 `soul_commit` 看到「当前会话是她醒来的那一次」就自动带 `together: false`。

唤醒消息用第一人称、带【我的时间】标记（模型一眼分得清这不是你在说话），措辞模板放在
`rp-soul/wake.md`，按段覆盖（和 dsh-world 的 alarm.md 一样）：

```
【我的时间】23:00 了，这是我说好做到的时间：「去洗澡」。
{你} 不在。接下来做什么由我决定：可以自己做点什么，也可以在这里给 {你} 留一句话。
做完用 soul_commit 记账，再用 plan_next 说好接下来做什么、做到几点；什么都不定，就按平常的时间叫我。
```

## 4. 设置页：新页签「唤醒」

- 会话下拉框：列出 DSH 会话（标题 + 最近更新时间），选一个；旁边标「当前指定」。
- 开关、每日次数、每日 token、安静时段、想你阈值、作息换段。
- 状态：下次唤醒（时间 + 理由）、今天已唤醒几次 / 用了多少 token、最近一次失败原因。
- 「现在叫醒一次」按钮（测试用，计入今天的次数）。
- 路由：`GET /rp-soul/wake`（配置 + 状态 + 会话列表）、`POST /rp-soul/wake`（改配置）、`POST /rp-soul/wake/now`。

## 5. 分阶段实现（每阶段测试全绿再往下）

1. **引擎**：`together`、`plan_next` op、`next-wake` 命令、上下文里的 `plan`；Python 测试用显式时间覆盖每种候选和安静时段。
2. **插件唤醒运行时**：`lib/wake.js`（定时器、额度、送达、turn/end、usage）+ 桥接层自动带 together；
   node 测试用假的 ctx / 时钟 / agent（不碰真实 DSH）。
3. **设置页**：「唤醒」页签与三个路由；client-bundle 测试。
4. **README** 与一次真机验证（需要你在 DSH 里开着插件试一晚）。

## 6. 风险

- **花钱**：默认关；每天次数 + token 双上限；超额当天不再叫。
- **刷屏**：「想你了」没回就翻倍间隔；安静时段；次数上限。
- **打断你**：会话在跑就推后，不会插进你正在进行的对话。
- **宿主接口变动**：`agent.steer`、`sessionController`、`session/event` 是 DSH 0.2.1-rc.2 的接口（dsh-world 也在用）；
  插件的 peerDependencies 写的是 `>=0.1.5-rc.1`，唤醒线要求 0.2.x，缺接口时整条线报「宿主不支持」并保持关闭，不影响其它功能。

## 7. 之后（不在这次）

- `reach_out`：系统通知 / 桌宠推送，挂在 agency 候选上（approach/request 才能发）。
- 每日回顾：晚上回看当天，写日记、更新她自己的自述（留快照）。
- 近期原文记忆：把最近 N 轮原话放进上下文。
