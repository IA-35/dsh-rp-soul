# 她的记忆：ABM / SCM / CLPA + 落盘的日记

以 RimTalk-ExpandMemory 为底改。核心是「衰减 + 检索」，不是「分层归档 + 定时压缩」。
三层记忆在账本里，日记在磁盘上。

| 层 | 里有什么 | 每小时衰减 | 容量 | 谁写 | 谁读 | 怎么消失 |
|---|---|---|---|---|---|---|
| **ABM** | 这段对话里的原话 | 不衰减 | 20 | 每次提交自动记 | **不读**（对话本身已在上下文里） | 满 20 条或搁置 1 小时 → 宿主起的子代理收成 1 条进 SCM，ABM 清空；小动作 24 小时直接丢 |
| **SCM** | 情景记忆，带「多久以前」 | 0.005 | 50 | ABM 汇总 | **读 3~5 条**（按分数） | 约一个月淡光；满 50 淘汰最不活跃的；**绝不清空** |
| **CLPA** | 她认定要一直记着的 | 不衰减 | 不限 | 汇总时模型自判（0~2 条）+ 里程碑自动进 | 参与检索（层级加成最低） | 只有你在设置页手动删改 |
| **日记** | 一天一篇，落盘 `journal/<session_id>/diary-<日>.md` | — | — | 23:30 之后由宿主起的子代理写（宿主收不了时由模型写） | 设置页「记忆」页签能翻；新会话第一轮带上最近一篇 | 不删 SCM |

## 1. 为什么是这样

RimTalk 的原始设计里，记忆是**一堆带活跃度的条目**：被想起就回升，长期没人提就淡掉。
它没有「层级」这种东西，只有「还记不记得」。

早先的版本加了「刚刚 → 今日 → 这几天 → 那些事 → 那些年」的归档流水线，
问题在于**每一层都在压缩**：一天的对话最后变成一条 ≤100 字的摘要，信息被毁掉；
而真正的检索（RimTalk 的内核）被挤到次要位置。这一版把它掰回来：

- 压缩只在**必须**的地方发生：ABM 满了 / 搁置一小时（一次性收成一条），和每晚写日记（落盘，不毁条目）。
- SCM 里的条目不因为「攒够多少条」被清空，它们按活跃度自己淡掉。
- 只有 SCM / CLPA 进上下文，且只取 3~5 条最相关的——不再靠层级加成硬塞。

## 2. 采集（不花模型调用）

每次提交记一条进 ABM：

- `remember` 有值就用它（她第一人称怎么记），没有就用 `summary`。
- `ctx.beats`（离屏片段）各记一条 `experience`。
- 不显著的 `npc_action` 记一条 `action`（这类不参与汇总，24 小时后直接丢）。

重要度 = `0.3 + min(0.5, 新增情绪的 |delta| 之和 / 30) + 0.2×里程碑`。
关系阶段前进、第一次立下约定 → 自动 `pinned`（不衰减、不清理、不占容量）。

模型这一轮没交账时，宿主在回合结束时把这几轮攒起来，攒够四轮（或 1200 字、或搁了半小时）才落一条
（`note-turn` 的 `text`）。一条 ABM 讲的是一件事：RimTalk 一轮就是一件事，DSH 的一轮可能只是「继续」，
逐轮记会让二十条的额度被噪声占满。它的重要度用同一把尺子：
最近一小时里冒出来、还没被哪一条记忆算过的事件型心事（`kind="memory"`，情境类的「在场」不算）按 |delta| 加起来。
「算过没有」按心事 id 记在 `counters["weighed_thoughts"]`：宿主记的条目不推进时钟，按时间比会把同一份心情算进每一条。
同一轮交过账就不再记（按 agent 记「这一轮交过」，回合结束时看完就清）；她自己醒来的那一轮没有「你说的话」，记成 `experience`。

「不许凭空造物」：写进记忆的文字只许用这次正文里真出现过的人、物、动作和主人亲口说过的话。

## 3. ABM → SCM

`abm_batch(state)`（`domain/memories.py`）判断要不要收：

- 池子 = ABM 里 `type in KEEPS`、非 pinned、**且不是当前这一回合**刚记的条目。
- 满了 20 条 → 要收。
- 或者池子里最新一条距今 ≥ 60 分钟（`ABM_IDLE_MINUTES`）→ 要收。
- 都不是 → 不收。

要收时 `state["requests"]["memory_fold"] = {"ids": [...]}`。平时由宿主在回合结束后起子代理去收
（`summarize-memory`）；桥接层交账时带上 `host_memory: true`，这次提交不交 `memory_fold` 也不驳，快照里也不写「该收了」。
只有宿主收不了（没有子代理服务，或连着失败三次、正在歇五分钟）时才退回「下一次提交必须带 `memory_fold`」。
设置页手点「立即汇总」也走同一条路，只是不等回合结束：先登记这批，再当场起子代理（`foldNow`）。
不管谁写：
`apply_fold` 把这些条目合成一条 `layer="scm", type="summary"` 的条目（正文 ≤300 字，`origin_ids` 记来源），
然后从 entries 里删掉这批，ABM 变空。`memory_keep` 里点名的、以及 pinned 的，改成进 CLPA。

> **批次是「全部攒着的」，不是固定 20 条**：满了 20 条那一刻开始要收，但之后 ABM 继续涨，
> 批次也跟着涨。收完一批，剩下的立刻组成下一批（`_recount_requests` 每次都会重算），
> 所以不会出现「收过一次 ABM 还是满的」。
>
> **手点的那一批是例外**：设置页「立即汇总」写进 `requests` 的批次带 `manual` 标记，
> 重算时原样保住，直到它真的被写掉。
>
> **宿主先收过了，模型再交也不驳**：子代理收完之后会在 `counters["host_paid"]["fold"]`
> 记下回合号；模型在上一份上下文里看到「该收了」、跟着这一回合又交 `memory_fold` 时，
> `before_turn` 放行（`pay_requests` 也不会再落一条没有来源的 SCM）。

## 4. 日记

- 定时任务，不是模型欠的账：`diary_request(state)` 在 23:30 之后才返回东西；**过了午夜还欠着的也照样返回**，不然 23:30 那次唤醒被推后（你在说话 / 会话在跑 / 额度用完），跨过零点就再也写不出来了。
- 取**最早一个还没写过的日子**的 SCM（`diary_sources`）——23:30 那会儿没人说话，第二天醒来也要补上昨天。
- `get-context` 每次读快照前重算一遍 `requests`：到点这件事可能发生在上一轮 commit 之后，不重算的话这一轮根本看不见「该写日记了」。
- `counters["last_diary_day"]` 记住写到哪天，同一天不写第二遍（后来的条目进第二天的日记）。
- `apply_diary` 不删任何 SCM，只给条目盖 `diary_day` 章。
- 落盘走 `service.py` 的 `_plan_journal` / `_flush_journal`：写 `journal/<session_id>/diary-<日>.md`，不同账本不会互相覆盖；写失败只是少一份日记，不挡提交。
- 谁写：平时是宿主在回合结束后起的子代理（`write-diary`），同收 ABM 一样不逼对话中的她停下来交；
  先收 ABM、再写日记，刚收进 SCM 的那条也进今天。宿主收不了时退回由模型在提交里写 `memory_diary`。
- 唤醒：`domain/wake.py:_diary_candidate` 在 23:30 给一个 `reason="diary"` 的候选，走现有唤醒线叫醒她；那一轮结束时子代理把日记写好。
- 读：最近一篇留在 `state["memory"]["diary_last"]`，上下文里是 `last_diary`；桥接层只在新会话的第一轮（她还没开过口）把它放进「想起来的」那一段。
  设置页「记忆」页签从磁盘读全部日记（`GET /rp-soul/engine/diaries`），新的在前。

## 5. 注入（RimTalk 的打分）

**ABM 不进上下文**——对话本身已经在里面了。只从 SCM / CLPA 里取：

```
score = 时间分 + importance × 场景重要度权重 + 关键词分 × 场景关键词权重
      + 层级加成（SCM 0.85 / CLPA 0.5）× 0.2
      + Pin 0.5 + 你编辑过 0.3 + activity × 0.1
时间分   = exp(−天数 × 场景时间衰减)；超出场景窗口的：exp(−超出天数 × 2) × 0.1
关键词分 = min(1, Jaccard(记忆关键词, 线索关键词) + 0.2 × 线索词在内容里出现的次数)
```

- 条数：brief **3 条**（`SCM_BRIEF`）、full **5 条**（`SCM_FULL`），低于 0.15（`THRESHOLD`）不要。
- **两处放的不一样**：每轮自动注入的「想起来的」那一段（动态 context `soul-recall`）只放被你这句话的关键词撞上的（`cued`）；
  只靠时间和层级排进前几名的其余几条在 `soul_state` 的结果里，模型想多回忆一点时自己翻。
  这一段和「当前现状」（`soul-engine`）分开：宿主只在文本变了时往对话尾部追加一份，跟着你这句话变的东西放进局面那段，
  局面就几乎每轮都要追加一整份。
- **快淡光的（activity < 0.025）除非 pinned 否则不进上下文**：光靠层级加成也过得了阈值，那样阈值就形同虚设。
- 线索从哪来：你这句话（装配系统提示词时从会话里取最后一条真实的用户消息）。
- 每行带 `layer` / `when` / `clear` / `text`。`when` 是「周一晚上 20:30」：周几 + 时段 + 钟点。
  钟点精确到分钟（账本按真实分钟走）；几月几号存在条目的 `at.day` 里，设置页用 `when_label`
  按日期分组显示，注入不重复念日期。

被这句勾起 → `reinforce` 把活跃度 +0.1（封顶 1.0），重新开始衰减。

### 常识库是另一条道

`domain/common.py`：一张**全局**的表，每行「关键词 + 权重 + 一条常识」，不挂会话、不衰减、不占用上面的名额。
只有这句话里出现某个关键词才进上下文，渲染成 `## 常识` 下面一行一条；一句话命中多条时按权重从高到低，
取几条在设置页调（2~4，`LIMIT_RANGE`）。它跟记忆的分工：**记忆是「你们之间发生过什么」，
常识是「这个词指的是什么」**——后者不该挤占前者的名额，所以不参与 SCM/CLPA 的打分。

模型在收 ABM / 写日记时顺手提的常识（`common`）**先挂着**（`pending`），你在设置页点「确认」（`approve-common`）才会被注入；
关键词和你确认过（或手动加）的那条一样时，模型改不动它。你手动加的直接生效。schema 6 迁移时，库里原有的模型提的那些也一并挂起。

## 6. 清扫

`maintain(state)` 每次提交后跑：

- ABM：`type not in KEEPS` 且非 pinned 且超过 24 小时 → 丢。
- SCM：`activity < 0.025` 且非 pinned → 忘。
- SCM 超过 50 条 → 淘汰最不活跃的（非 pinned）。
- CLPA 永不清扫。**ABM 不在这里清空**——由 `apply_fold` 清。

## 7. 设置页

记忆页签是 ABM / SCM / CLPA 三层的纵向时间轴，按天分组，透明度 = 活跃度。
点开一条能改内容 / 重要度 / 活跃度 / 关键词 / 备注 / Pin，也能删（留审计）。
两个按钮：「立即汇总」（把当前 ABM 全收进 SCM）、「立即写日记」。

## 8. 参数（已定）

| 层 | 衰减率 | 多久被忘（一直没被想起的话） | 依据 |
|---|---|---|---|
| SCM | 0.005 | 约 30 天 | 「情景级」的量级：跨几次对话还记得，一个月后淡掉 |
| CLPA | 不衰减 | 永不 | 她认定的事，只有你手动删 |

`ABM_IDLE_MINUTES = 60`、`DIARY_MINUTE = 23*60+30`、`CLEAN_BELOW = 0.025`。

写进上下文时不报活跃度的小数，报四档：`CLEARNESS = ((0.7, "记忆犹新"), (0.4, "大概记得"), (0.1, "有些模糊了"), (0.0, "记不起来了"))`。
边界对着 SCM 的曲线取：0.7 / 0.4 / 0.1 分别是 3 天、7.6 天、19 天。

## 9. 迁移

`normalize_legacy` 把旧层名映射过来（`now→abm`、`temp/days→scm`、`events/years/chapter→clpa`），
并清掉旧请求键（`memory_summary` / `memory_journal` / `memory_archive`）。

旧存档的 `real_at` / `real_start` 缺失时，由 `repo.load_session` 用会话的 `created_at` 补上——
否则续写全靠它们算「过了多久」，缺一个，整局就从此刻重新起算，中间那几天被静默吃掉。
