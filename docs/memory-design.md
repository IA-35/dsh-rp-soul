# 记忆方案：以 RimTalk-ExpandMemory 为主

目标：她的记忆像人一样按「时间远近 + 还记不记得」流转——刚发生的清楚、这几天的还在、
那些事只剩梗概、那些年只剩里程碑——而不是按项目/主题建条目（mnemon 那种）。

主体照搬 [RimTalk-ExpandMemory](https://github.com/sanguodxj-byte/RimTalk-ExpandMemory)（MIT）的四层记忆、
活跃度衰减、Pin、每日总结、定期归档、配额注入和时间轴工作台。下面的数字都是它源码里的默认值
（`RimTalkSettings.cs`、`DynamicMemoryInjection.cs`、`MemoryMaintainer.cs`），改动的地方逐条写明为什么。

---

## 0. 四层和现有的巩固链：替换，不是并存

引擎现在已经有一条三段巩固链：每回合一条摘要（`memory.turns`，最多 40 条）→ 跨天或满 20 回合由模型写一条
章节摘要（`chapters`）→ 章节超过 10 条再把最早 5 章合成前情（`prologue`）；被挤出去的都进归档表，之后不再回到上下文。

之前说「不要再起一套四层」，指的是**别在这条链旁边再并排建一套**——那样会有两套总结、两份文本、互相对不上。
这份方案的做法是**用 RimTalk 的四层把这条链整个换掉**：

| 现有 | 换成 | 迁移时 |
|---|---|---|
| `memory.turns`（回合摘要） | 「刚刚」「这几天」的记忆条 | 按时间分进两层 |
| `chapters`（章节摘要）+ `requests.chapter_summary` | 「那些事」+ 每日总结请求 `memory_summary` | 旧章节转成「那些事」条目 |
| `prologue`（前情）+ `requests.prologue` | 「那些年」+ 定期归档请求 `memory_archive` | 旧前情转成一条「那些年」 |
| 归档表里的旧回合 | 不再参与（它们早已被章节概括过） | 原样留着，导出照旧 |

为什么不保留现有结构、只在上面加衰减（上一轮的建议）：你定了以 RimTalk 为主，而它的 Pin、编辑、层间迁移、
按条打分注入都要求「每条记忆是一个有活跃度、重要度、关键词的条目」；现有的章节和前情只是几段字符串，
在上面挂这些元数据，最后还是会长成同样的结构，不如直接换。代价是改动面更大（状态 schema 3、一次迁移）。

## 1. 四层（照搬）

| 层 | RimTalk | 我们的叫法 | 衰减（每小时） | 容量 | 到上限 / 到期 |
|---|---|---|---|---|---|
| ABM | Active | 刚刚 | 不衰减 | 6 | 存活 24 小时 → 对话类迁入「这几天」，动作类直接丢 |
| SCM | Situational | 这几天 | 0.05 | 20 | 超容量按活跃度最低淘汰 |
| ELS | EventLog | 那些事 | 0.00384 | 50 | 超容量的最旧非 Pin 条直接改层进「那些年」（不摘要） |
| CLPA | Archive | 那些年 | 0.0003（RimTalk 是 0.00128，见第 9 节） | 50 | 只被衰减 / 清理 |

- 活跃度 `Activity *= 1 - rate`，不 clamp；`Activity < 0.025` 且没 Pin → 删除。
- Pin 的不衰减、不清理、不参与容量淘汰。
- 每条记忆：`id / origin_ids / layer / type / content / importance / activity / at（发生时刻）/ keywords / note / pinned / edited`。

**改动 1：衰减按时间现算，不逐小时写回。** RimTalk 每游戏小时把每条乘一次；我们的引擎按真实时间结算、
只在回合提交时运行，所以存「上次被触碰时的活跃度 `a0` + 触碰时刻 `t0`」，读的时候
`activity = a0 × (1 − rate)^(小时数)`——数学上和逐小时连乘完全相同，但平时只读不写，
撤销 / 存档 / 导出天然一致。层迁移、清理、容量淘汰在每次提交的结算阶段统一跑一遍（和心情衰减同一处）。

**改动 2：`layer` 是唯一来源。** RimTalk 自己列了「Layer 字段可能与实际所在列表不一致」的已知缺陷；
我们只存一个列表、每条带 `layer`，各层是按 `layer` 过滤出来的视图，不存在不一致。

## 2. 记忆从哪来（采集，不花模型调用）

RimTalk 从对话轮（RoundMemory）、工作、战斗里采集。我们对应：

| 来源 | 类型 | 写进哪层 | 内容 |
|---|---|---|---|
| 每次提交的回合 | 对话 `conversation` | 刚刚 | 回合摘要；有她的第一人称记法就用它（见下） |
| 离屏片段 / 唤醒回合（她一个人的时间） | 经历 `experience` | 刚刚 | 片段摘要 |
| 不重大的 `npc_action` | 动作 `action` | 刚刚 | 动作文本；到期直接丢，和 RimTalk 一样 |

- **改动 3：可选的第一人称记法。** 提交多一个可选字段 `remember`（≤60 字）：她会怎么记得这件事
  （「他迟到了一个钟头，我等得有点烦，后来他把伞留给了我」）。不写就用第三方视角的摘要。
  这一句是「生活化」的关键：记忆是她的，不是旁白的。
- **重要度（0–1）** RimTalk 按采集类型给；我们按这一回合的情绪分量算，免费且是她自己的：
  `0.3 + min(0.5, 这回合新增情绪的 |delta| 之和 / 30) + 0.2（关系阶段变化或立下约定）`。
- **关键词**：内容按两字一组（bigram）切出来，加上她的名字、约定标题。中文不需要分词库。
- 关系阶段前进、第一次立约这类里程碑**自动 Pin**（RimTalk 只有手动 Pin；这是我们的小补充，设置页可以取消）。

## 3. 每日总结与定期归档（照搬，执行者换成会话里的模型）

| | RimTalk | 我们 |
|---|---|---|
| 每日总结 | 每天 `summarizationHour`（默认 0 点），把「刚刚 + 这几天」按最旧完整的一天分组，一次请求写成一条「那些事」，≤80 字；新条 importance = 源均值、时刻 = 最新源、关键词去重合并；成功后源的 id 记进 `summarizedIds` 防重复 | 跨天后的第一次提交，引擎在 `requests.memory_summary` 里给出那一天的源记忆，模型在这次提交里写 `memory_summary`（≤80 字）；规则同左，源 id 记进新条的 `origin_ids` |
| 定期归档 | 每 15 天把「那些事」所有非 Pin 条写成一条「那些年」篇章，≤60 字 | 同样每 15 天，`requests.memory_archive` → 提交里写 `memory_archive`（≤60 字） |
| 失败 | AI 队列重试，失败不改源 | 提交被驳回就什么都没变，下一次提交再要（和现在的章节摘要一样） |

- RimTalk 的总结提示词是「提炼地点人物事件、相似事件合并标注频率、极简」。我们沿用，并改成她的口吻：
  「用第一人称写那一天对我来说发生了什么、我是什么感受，相似的事合并、注明次数，不超过 80 字」。
- 这套**取代**引擎现有的「章节摘要 + 前情合并」（turns → chapters → prologue）：它本来就是三层巩固，
  只是没有衰减和检索。迁移时旧章节进「那些事」，旧前情进「那些年」，不留两套。
- RimTalk 的 callback 没有 ID / 版本校验（作者列的已知债）；我们的总结走提交，天然带 revision、要么全收要么全驳。
- 唤醒线（另一边在做）落地后，可以让夜里那次唤醒顺手完成总结，不必等你第二天第一句话。

## 4. 注入：配额收割（照搬）

**先放最近几轮对话，再按分数补满。**

1. 「刚刚」里最近 3 轮（`maxABMInjectionRounds = 3`）原样放：你说的话（截短）+ 她的原话。
2. 剩余配额 = 10（`maxInjectedMemories`）− 已放条数，从其余三层打分取前 N，低于 0.15（`memoryScoreThreshold`）不要：

```
score = 时间分 + importance × 场景重要度权重 + 关键词分 × 场景关键词权重
      + 层级加成（刚刚 1 / 这几天 .7 / 那些事 .4 / 那些年 .2）× 0.2
      + Pin 0.5 + 你编辑过 0.3 + activity × 0.1
时间分   = exp(−天数 × 场景时间衰减)；超出场景窗口的：exp(−超出天数 × 2) × 0.1
关键词分 = min(1, Jaccard(记忆关键词, 线索关键词) + 0.2 × 线索词在内容里出现的次数)
```

- **线索**从哪来：你这一句话（`soul_state` 多一个可选参数 `cue`，桥接层把你最新的消息传进去）、
  作息此刻在做什么、快到期的约定标题、她当前的情绪事由。
- **场景动态权重**（实现时对照 RimTalk 源码改正：动态模式下时间分不再乘权重，权重来自 `SceneAnalyzer`）：
  你在 = 它的社交场景（时间衰减 0.05 / 重要度 0.2 / 关键词 0.25，窗口 30 天，往事容易被勾起）；
  她一个人（没有线索）= 它的普通场景（0.3 / 0.3 / 0.35，窗口 3 天，只看最近）。
  设置里那组 0.3 / 0.3 / 0.4 是它非动态模式的权重，动态注入不用。
- **改动 4：去掉关系加成。** RimTalk 的关系加成是「记忆里的那个人跟当前角色多亲」；只有你们两个人，这一项恒定，不要。
- 输出格式：`[那些事 · 三天前 · 周三晚上] 他迟到了一个钟头……`——生活化的时间说法由引擎的日期和真实时间推出（几天前、星期几、时段）。
- 被注入的记忆算「被想起」：`a0` 回到当前活跃度并加 0.1（封顶 1）、`t0` 刷新。这一点 RimTalk 没有（它只衰减），
  是从 MemoryBank 借来的「越想越牢」，让常被提起的事不容易淡掉。

### 常识库 ↔ 她知道的事

RimTalk 的常识库（世界设定）走另一条：标签精确匹配为主，最多 5 条（`maxInjectedKnowledge`），阈值 0.1，
向量检索只是可选补充。我们的对应物就是事实表：

- 事实保持原样（只增不删，不改协议 7），不并进记忆层；
- 注入时按线索关键词精确匹配取最多 5 条，**包括只有她知道的事**——现在的上下文只给「你知道的事实」，
  她的秘密和表面配合时的真实打算模型根本看不到，这顺带补上。
- 不做向量检索（要外部 embedding 服务；RimTalk 自己也写了「向量只作补充，不能取代精确匹配」）。

## 5. 设置页「记忆」页签（RimTalk 工作台的简化版）

- 纵向时间轴看「刚刚 / 这几天 / 那些事」：按天分隔、「N 天前」、卡片透明度 = 活跃度、按层过滤。
- 顶部一条「那些年」篇章带（RimTalk 是可缩放的横向 Chronicle；我们先做静态列表，够用再加缩放）。
- 右侧详情：查看与编辑切换，可改内容 / 重要度 / 活跃度 / 关键词 / 备注、Pin、删除（删除留审计，和删情绪一样）。
- 底部：「立即总结」「立即归档」——设置下一次提交的请求，不在设置页里直接调模型。
- 路由：`GET /rp-soul/engine/memories`、`PUT /rp-soul/engine/memory`（编辑 / Pin）、`DELETE /rp-soul/engine/memory`、
  `POST /rp-soul/engine/memory/request`（总结 / 归档）。

## 6. 存储与迁移

- 记忆条放在会话状态里（`state.memory.entries`），和现在的回合摘要、章节一样随状态走：撤销、读档、导出都不用额外处理。
  四层满额约 126 条、每条约 200 字节，状态块多 25 KB 左右，可以接受。
- 状态 schema 3：现有 `memory.turns`（最近 40 条摘要）按时间分进「刚刚 / 这几天」，`chapters` 进「那些事」，
  `prologue` 进「那些年」；`requests.chapter_summary / prologue` 换成 `memory_summary / memory_archive`。
  迁移规则和上一次一样写成纯函数，数据库迁移和导入共用。

## 7. 不做的（和理由）

- **向量检索**：要外部服务；单人场景下关键词 + 线索已经够，RimTalk 自己的结论也是精确匹配为主。
- **独立的记忆数据库**：和状态双写必然不一致。
- **回忆牵动心情**（想起那件事 +2）：会形成「想起难过的事 → 更低落 → 更容易想起难过的事」的回路。先不做；
  以后要做，只在你提起那件事时触发、幅度封顶、同一条一天最多一次。
- **RimTalk 的 AI 队列 / 多配置 fallback**：我们没有独立的模型调用，总结走提交。

## 8. 分阶段实现（每阶段测试全绿再往下）

1. **记忆条与四层**：采集、`remember` 字段、重要度、关键词、现算衰减、层迁移 / 清理 / 容量、自动 Pin；状态 schema 3 迁移。
   测试用显式时间推进验证每层的到期、衰减到 0.025 被删、Pin 不动、容量淘汰。
2. **每日总结与归档**：`memory_summary / memory_archive` 请求与提交字段、origin_ids 防重复；取代章节 / 前情。
3. **注入**：配额收割、打分、线索（`soul_state` 的 `cue`）、常识库（事实精确匹配，含她知道的事）、被想起加强；
   上下文预算内（brief 6 KB）。
4. **设置页「记忆」页签**与路由。
5. **README**，以及在 DSH 里聊几天看记忆流转（需要你试用）。

## 9. 参数（已定）

**时间节奏**：RimTalk 的衰减率按小时算，放到真实时间里，从满活跃度降到 0.025（被删）分别要：

| 层 | 衰减率 | 多久被忘（一直没被想起的话） | 结论 |
|---|---|---|---|
| 这几天 | 0.05 | 约 3 天 | 正好就是「这几天」，照搬 |
| 那些事 | 0.00384 | 约 40 天 | 一个多月，合适，照搬 |
| 那些年 | 0.00128 | 约 120 天 | 「那些年」四个月就没了，不对；改成 **0.0003，约 1 年 5 个月** |

被想起会把活跃度拉回去，所以常被提起的事远比这长；重要的可以 Pin。「刚刚」存活 24 小时、
跨天后第一次提交做每日总结、每 15 天归档，都按真实时间照搬。

**里程碑自动 Pin**：要。关系阶段前进、第一次立下你们之间的约定，这两类自动 Pin；设置页可以取消。

**注入条数**：完整上下文照搬 10 条（最近 3 轮 + 打分补 7 条）；brief 上下文只有 6 KB，用 **8 条**（最近 3 轮 + 打分补 5 条），
每条正文截到 80 字，合计约 1.5 KB；超预算时先砍打分补的那几条，最近 3 轮最后才动。
