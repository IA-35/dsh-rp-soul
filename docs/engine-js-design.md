# 引擎重写：JS、放进插件进程、子模块可拔插

分支 `refactor/engine-js`。`main` 在新引擎跑稳之前不动。

一句话：**Python 侧车换成插件进程里的 JS，存储用 Node 自带的 SQLite（`node:sqlite`）；一个很小的内核只管「你和她」的时间、事实和
她的反应；其余收成四个模块——情绪、记忆、常识、唤醒，每个都能在设置页单独开关。
所有时间都是真实时间，没有游戏时钟，也没有回合。**

---

## 0. 为什么重写

| 现在 | 代价 |
|---|---|
| Python 侧车 + stdio 协议（`engine-client.js` 407 行、`__main__` 255 行） | 找 Python、进程起不来、卡死要杀、超时、Windows 换行、两边 schema 对齐测试 |
| 从 adult-tension 移植，多角色写法还剩 67 处（`characters` 字典、`npc_id`、在场名单、`her>player` 边） | 每条规则都要先「找到那个角色」 |
| 模型交账：12 个 op、5 种 action_mode、5 种回应、19 个内容标签、`acts_on_her` / `player_authorized` | 上周实测交账失败率 69% |
| `service.py` 1816 行 / 97 个函数，40 个命令；记忆模块一改就牵动引擎、桥接、设置页三处 | 改一处穿三层 |
| 「模块」只是引擎里的四个钩子文件，开关不了；lite 版只能另开分支砍代码 | 想去掉一个功能就得维护一条分支 |
| 游戏时钟（第几天 + 当天第几分钟）+ 真实时间锚点 `real_at`，两套时间来回换算；`turn` 回合号 | 跨午夜、长时间离开、老存档缺锚点，都出过「时间被吃掉」的 bug；回合号还在撤销、存档、日志里到处被当序号用 |

运行环境：**Node ≥ 24.12**（`package.json` 的 `engines` 写上）。已确认 Node 24.13 上 `node:sqlite` 能用；
它在 24 里仍标着实验特性，启动时会打一条 ExperimentalWarning，不影响功能。
旧库里的状态是 `zlib` 压缩的 JSON，同一个 `node:sqlite` 能打开旧库、`zlib.inflateSync` 能解压，所以旧存档能导入。

### 0.1 做完是什么样（验收标准）

三条都达到才把默认引擎切到新的；没达到就继续改，不凭感觉：

1. **交账一次过的比例 ≥ 90%**（现在 31%：26 次里 8 次）。用 `scan_commits.mjs` 在真实会话里量，至少 50 次交账。
2. **工具说明比现在小**：四个模块全开时，三个工具的定义加起来 < 现在的 11 KB。
3. **旧账本导入后逐项对得上**：她的心情与每条心事、态度（信任 / 张力 / 阶段）、事实与谁知道、未结束的约定、安排。

重写期间**旧引擎冻结**：`main` 只修严重 bug，不加功能，免得两边一直追不齐。

## 1. 原则

1. **只有你和她。** 状态里是 `her` 和 `you` 两个固定位置，没有「第几个角色」。
2. **内核很小，其余都是模块。** 内核关不掉；模块各自开关，关掉的模块不参与交账、不出现在快照里、
   它的字段也不出现在给模型的工具说明里（模型要记的东西随之变少）。
3. **模块之间不直接调用。** 读别人用 `ctx.ask("mood.band")`，对方关着就拿到 `null`；
   影响别人用 `ctx.emit("event.failed", …)`，对方关着就没人听。所以关掉任何一个模块，其它照常跑。
4. **引擎能推出来的，模型不写。** 时间、心情数值、冷却、到期、要不要补离屏片段，全由引擎算。
5. **核心是纯函数。** `commit(state, input, now) → { state, receipt }`，不碰数据库、不读时钟、不改入参。
   数据库、时钟、文件、DSH 钩子只在最外层。
6. **全有或全无**照旧，但只驳回会把账本弄坏的东西；能补默认值的补上，用不上的丢掉并在回执里说一句。
7. **状态就是一个 JSON**，每个模块一块切片；撤销 = 回到上一份快照。
8. **只有真实时间。** 没有游戏时钟，没有「第几天」，所有时刻都是带时区的 ISO 时间戳。
9. **没有回合。** 交账只是「此刻发生了一件事」的一条记录，不推进任何东西；没有回合号，没有「每 N 回合」的规则。

### 1.1 时间怎么算

- **时刻**：一律存带时区偏移的 ISO 字符串（`2026-11-11T21:40:00+08:00`），时区取本机。比较、相减都用毫秒。
- **「现在」只从外面传进来**：所有纯函数都收一个 `now`，自己不读时钟。测试里随便造时间。
- **状态只在读的时候算**：心事过没过期、衰减到多少、约定到没到期、冷却好没好，全是「拿记下的时刻和 `now` 比」现算出来的，
  不存一个「结算到哪了」的钟。所以长时间离开、电脑睡眠、改系统时间，都不会出现「中间几天被吃掉」——没有东西可吃。
- **隔了多久**：`now − you.last_said_at`（你上次说话的时刻）。她自己醒来的那一次不更新它。
- **一段相处**：两次交账之间隔了 60 分钟以上，就是新的一段；`scene.since` 记新一段开始的时刻。
- **一天**：按本机日历日算（`toLocaleDateString`）。日记、「今天」「昨天」、跨天归档都看日历日，不看第几天。
- **作息**：人设里的作息写「几点到几点」（`08:00-18:00 上班`），按本机钟点对照。
- **只由时间决定的结果，读的时候现算，不写进账本；只有模型或你真做了的事才写进去。**
  例子：约好「周六上午 10 点去看海」没去成，她该有一条「约定落空」的心事。这条心事**不写进账本**，
  而是每次读局面时，看到约定还挂着、到期时间已经过了，就当她有这条心事，从周六 10 点开始算。
  这样你周一才回来、她被唤醒时没有交账、撤销了上一次交账，结果都一样，不会对不上。
  同类的还有：冷却好没好、是不是新的一段相处、该不该补离屏片段、作息此刻在哪一段。
- **交账时顺手清理**：commit 在 `now` 这一刻把已经彻底没影响的东西清掉（衰减到 0 的心事、早已结束的约定），
  只为账本不越攒越多；清不清，读出来的结果都一样。

> 下文的「一轮对话」指 DSH 里你说一句、她回一句，那是宿主的事，引擎不数它。

### 1.2 没有回合之后，原来靠回合的东西怎么办

| 原来 | 现在 |
|---|---|
| 回合号当撤销序号 | 每次交账一个 `id`（时间戳 + 随机后缀），快照按它存；撤销 = 回到上一份 |
| 回合号当并发保护 | `revision`：账本每写一次加一，提交时带上，对不上就是「局面变了」。它只防并发，不参与任何规则 |
| 「最近 N 回合」「每 5 回合给一次完整上下文」 | 全改成时间：最近 30 分钟、距上次完整上下文 15 分钟（`time-not-turns` 那次已经改过一遍，这次连回合号本身也拿掉） |
| `continue` / `wait` 这种「时间在走」的回合 | 不需要：时间本来就在走，没有东西要靠交账来推进 |
| 存档、日志、活动页显示「第 N 回合」 | 显示时刻（「11 月 11 日 21:40」） |

## 2. 内核与模块

| 名字 | 是什么 | 能关？ | 依赖 |
|---|---|---|---|
| 名字 | 管什么 | 交账里归它的字段 | 依赖 |
|---|---|---|---|
| **内核**（不能关） | 真实时间、一段相处、事实与「谁知道」、她这一次的回应与状况、**你们的约定和她自己的事**（到期 / 兑现 / 取消）、作息（从人设读）、安全边界与亲密门禁、交账流水、存档 / 撤销 / 导出 | `summary` `her` `learned` `reveal` `promise` `open` `quotes` `tags` `consent` | — |
| `mood` **情绪** | 心事与心情档位、情境心事表、行为门禁；**她对你的态度**（信任 / 张力 / 阶段）；**她下一步可能做什么**（自主行动候选、重大行动冷却）——这三样都是「她此刻怎么想、会怎么做」 | `feel` `bond` `act` | — |
| `memory` **记忆** | 每轮对话结束自动记、攒批、筛选 / 汇总 / 日记子代理、记忆注入 | 无（宿主自己整理，不让模型交作业） | 硬：宿主有子代理服务；软：`mood`（情绪分量定轻重） |
| `common` **常识** | 关键词 → 常识，全局一张表，命中才注入；模型提的要你确认 | `common` | — |
| `wake` **唤醒** | 你不在时她的时间：她的安排（plan）、隔久了补一段「你不在时她做了什么」（离屏片段）、下一次该醒的时间（她的安排 / 约定到期 / 想你了 / 作息换段）、定时器与送达 | `plan` `away` | — |

为什么这么收：

- **关系、自主行动并进情绪。** 三者本来就互相读：心情低落时不接受关系推进；自主行动的候选按心情和态度打分；
  信任变化会变成一条心事。放在一个模块里，这些就是模块内部的事，不用跨模块传信号。
- **约定、作息进内核。** 约定是「你们之间说定的事」，和事实一样是账本的骨架，唤醒和情绪都要读它；
  作息是人设的一部分。两者都不值得单独开关。
- **离屏片段并进唤醒。** 都是「你不在的时候她在干什么」：关掉唤醒，她就只活在你在的时候，也不再要求补离屏片段。

依赖：

- **软依赖**：用得上就用，对方关着也能跑（`memory` 用情绪分量定一条记忆的轻重，情绪关着就按默认轻重）。
- **硬依赖**：缺了就开不起来，设置页上那个开关是灰的并写明原因。
- **lite 版不再是一条分支**：就是「`memory` 关掉」这一个设置。

### 2.1 一个模块长什么样

每个模块一个目录 `lib/engine/modules/<id>/`，导出同一种形状：

```js
export default {
  id: "mood",
  label: "情绪",
  requires: [],                      // 硬依赖（模块 id 或 "host:subagents" 这种宿主能力）
  settings: { /* 默认设置，设置页能改 */ },

  // ---- 引擎这一半（纯函数，拿到的是自己那块切片） ----
  init(persona, now) { return { /* 开局时的切片 */ } },
  view(slice, now) { /* 这一刻的样子：拿记下的时刻和 now 比，现算过期 / 衰减；不改切片 */ },
  tidy(slice, now) { /* 交账落定时把已经过期的清掉，返回新切片 */ return slice },
  fields: { feel: FeelSpec },        // 交账表里归它管的字段（校验 + 给模型的说明都从这里生成）
  validate(slice, input, ctx) { /* 返回问题清单 */ },
  apply(slice, input, ctx) { /* 返回新切片；可 ctx.emit 通知别人 */ },
  on: { "event.failed": (slice, payload, ctx) => slice }, // 听内核或别的模块发的信号（约定没兑现 → 一条心事）
  answers: { band: (slice, ctx) => "normal" },             // 别人 ctx.ask("mood.band") 时回答
  project(slice, ctx) { /* 快照里的几行 + soul_state 里的字段 */ },

  // ---- 宿主这一半（可选：要碰 DSH 才写） ----
  host: {
    onTurnStopping(api, agent) {},   // memory 用：DSH 这一轮对话结束时记一笔
    onTimer(api) {},                 // wake 用：到点叫醒
    routes: { "GET /memories": … },  // 设置页的接口
  },
  panel: "memory",                   // 设置页的页签（模块关掉时页签隐藏）
};
```

模块注册表是固定的一个列表（内置的这几个），不从磁盘动态加载——可拔插指的是**开关**，不是装第三方代码。

### 2.2 开关

- 存在 `rp-soul/config.json` 的 `modules: { "memory": false, … }`，设置页「引擎」卡片里一排开关，
  每个模块自己的设置也在那里。
- **关掉**：切片原样留在账本里，不再结算、不再注入、它的字段从工具说明里拿掉；宿主那一半（钩子、定时器、路由）一起停。
- **再打开**：什么都不用补——切片里记的是时刻，打开那一下 `view(slice, now)` 现算就是对的（关着期间该过期的心事自然算作过期）。
- 工具说明随开关变，所以开关那一下会让前缀缓存失效一次；平时不变。

## 3. 模型交账：新的 `soul_commit`

整张表由「内核字段 + 开着的模块的字段」拼出来，除了 `summary` 全部可选：

```jsonc
{
  // ---- 内核 ----
  "summary": "这一次发生了什么，第三方一两句（≤120）",
  "her": {                           // 她这一次的反应。主人冲着她做了什么 / 向她要了什么时，写 response
    "response": "refuse | negotiate | partial | surface | genuine",
    "did": "她做了什么（≤120）",
    "state": { "add": [{ "kind": "asleep", "text": "睡着了", "minutes": 120 }], "remove": ["busy"] }
  },
  "learned": [{ "key": "rain.umbrella", "text": "你把伞留在门边", "who": "shared | you | her | inner" }],
  "reveal": ["her.secret.letter"],
  "promise": [{ "title": "周末去看海", "due": "2026-11-15T10:00" }, { "done": "e3" }],   // 到期写真实时刻，或 in_minutes
  "open": "停在哪里（≤80，不写沿用上一个）",
  "quotes": ["值得留下的原话"],
  "tags": ["romance_light"], "consent": false,   // 碰边界、亲密场景时才需要

  // ---- 模块（关掉的模块，它的字段不出现） ----
  "feel":    [{ "label": "他把伞留给了我", "delta": 6, "because": "rain.umbrella" }],    // 情绪：心事；because 可以是事实的 key，也可以直接写一句话
  "bond":    { "trust": 1, "tension": 0, "stage": "advance", "reason": "…" },             // 情绪：态度
  "act":     { "significant": true, "kind": "approach" },                                 // 情绪：给 her.did 打标
  "away":    "主人不在时她做了什么（≤120）",                                               // 唤醒：离屏片段
  "plan":    { "note": "去洗澡", "until": "23:00" },                                      // 唤醒：她的安排
  "common":  [{ "key": ["ds"], "content": "…" }]                                         // 常识
}
```

和现在比砍掉的：

| 现在 | 新的 | 理由 |
|---|---|---|
| `action_mode` 五档、`acts_on_her` | 没了 | 它们唯一的用处是「冲着她的事要有她的回应」，可引擎看不出主人这句话是不是冲着她，校验不了。改成工具说明和人设里的一句话：「她的反应由她自己决定，主人的话不能替她定」 |
| `rewrite` + `player_authorized` + `add_fact(origin: retcon)` | `learned[].retcon: true`，要求 `consent` | 改设定是少见操作 |
| `replaces_turn` | 没了 | 撤销一次再交，效果一样 |
| `action_mode: continue / wait`（「时间在走」的回合） | 没了 | 时间本来就在走，不靠交账推进 |
| 十二个 op | 上面十来个扁平字段 | 一个字段一件事，不用记 op 的字段名 |
| `content_tags` 必填 | `tags` 可选 | 只有碰边界、亲密场景时才有意义 |
| 事件 6 种 | 2 种：约定 `promise`、她自己的事 `task` | rumor / opportunity / chance 是多角色世界的东西 |
| `memory_fold` / `memory_diary` / `remember` | 不在交账里 | 记忆模块由宿主在每轮对话结束后自己整理，不让模型交作业 |

保留的硬规则（引擎照旧驳回），各归各的模块，模块关掉规则也跟着不生效：

- 内核：**亲密门禁**——交账带了 `intimate` / `explicit` 标签时，要 `consent`，且她的回应是 partial / genuine
  （或她主动），她睡着 / 喝醉时不行。这是引擎唯一能确定「冲着她」的地方，也是最不该放松的一条。
  碰到主人登记的硬边界直接驳回；
- 情绪：心事要有来由——`because` 是她知道的事实的 key，或者直接写一句话（引擎自动把它记成一条「她心里的」事实，
  模型不用先 `learned` 再引用）；closed / break 档回应长度受限、不接受关系推进；
  重大行动要过冷却、要是候选里的；
- 唤醒：隔了一小时以上要有 `away`（快照里会提前说）。

两个容易混的字段，说明里各给一个反例：

- `learned`（事实）是你们这段关系里的事：「他养了一只猫」「他不喝冰的」。
- `common`（常识）是换一局也成立的客观知识：「DS 指的是 deepseek」。他养猫不是常识，deepseek 是什么也不是你们之间的事。

## 4. 状态长什么样

```jsonc
{
  "v": 1,
  "persona": { "id": "lin_wan", "revision": "…" },
  // ---- 内核 ----（没有 clock、没有 turn；所有时刻都是 ISO 字符串）
  "revision": 128,                                   // 只防并发
  "started_at": "2026-10-22T08:05:00+08:00",
  "her": { "name": "林晚", "conditions": [{ "kind": "asleep", "text": "睡着了", "until": "…" }] },
  "you": { "name": "你", "last_said_at": "2026-11-11T21:40:00+08:00" },
  "facts": { "f1": { "key": "rain.umbrella", "text": "…", "who": "shared", "at": "…" } },
  "scene": { "since": "…", "responses": [] },
  "last_commit_at": "…",
  "log": [ /* 最近 40 次交账：{ id, at, summary, open, quotes } */ ],
  "safety": { "paused": false, "boundaries": [] },
  "prefs": { "pace": "standard", "explicitness": "standard" },
  // ---- 模块切片：每块只有它自己的模块读写 ----
  "events": { "e1": { "kind": "promise", "title": "周末去看海", "due": "…", "state": "pending" } },
  "modules": {
    "mood":   { "base": 55, "thoughts": [{ "label": "…", "delta": 6, "since": "…", "until": "…" }],
                "bond": { "trust": 1, "tension": 0, "stage": "familiar", "history": [] },
                "major_action_at": null },        // 冷却：拿它和 now 比
    "memory": { "entries": [], "batch": [] },
    "wake":   { "plan": { "note": "去洗澡", "until": "2026-11-11T23:00:00+08:00" } }
  }
}
```

常识库是全局的，不在单局状态里，存自己的表。

## 5. 代码怎么拆

```
lib/engine/
  core/
    schema.js     交账表：内核字段 + 开着的模块字段 → 校验器与给模型的说明（一份定义生成两样）
    time.js       ISO 时刻的解析 / 比较 / 相加、隔了多久、本机日历日、钟点、新的一段相处
    facts.js      事实与「谁知道」
    events.js     你们的约定、她自己的事：到期、兑现、取消
    her.js        她的回应、状况、作息、安全边界与亲密门禁
    commit.js     一次交账：各模块 view(now) → 校验 → 应用 → 信号 → tidy(now) → 回执
    context.js    快照（局面）与 soul_state 的返回：内核几行 + 各模块 project
    registry.js   模块清单、开关、依赖检查、ctx.ask / ctx.emit
  modules/
    mood/     index.js  thoughts.js  bond.js  agency.js      情绪
    memory/   index.js  layers.js  batch.js  host.js         记忆
    common/   index.js                                       常识
    wake/     index.js  plan.js  offscreen.js  schedule.js  host.js   唤醒
  store.js        存储适配层：读写账本、撤销快照、流水、存档、常识；外面只认它的接口，底下换实现不影响别处
  index.js        对外的 API：open(dataDir)、context()、commit()、undo()、存档、模块开关、设置页读写
```

每个文件只管一件事，目标都在 300 行以内。

**存储用 SQLite**（`node:sqlite`，一个文件 `rp-soul/engine/engine-v2.db`），六张表：

| 表 | 放什么 |
|---|---|
| `ledger` | 一行一局，整份状态 JSON（加 `revision`、`updated_at`） |
| `snapshots` | 撤销用，按交账 `id` 存整份状态，每局留最近 30 份 |
| `log` | 交账流水，一行一次（给「自主行动记录」页），每局超过 2000 行删最老的 |
| `slots` | 命名存档 |
| `common` | 常识库（全局，不挂局） |
| `meta` | 版本号，迁移用 |

- 一次交账（写快照 + 写账本 + 记流水）在**一个事务**里，要么全成要么全不成。
- WAL 模式；进程内同一时刻只允许一次写，并发靠 `revision` 防住。
- 只有 `store.js` 认识 SQLite，外面只认它的接口。
- 新库和旧库（Python 引擎的 `engine.db`）分开放：新的叫 `engine-v2.db`，旧的原样留着，导入从旧库读。

桥接层 `engine-bridge.js` 直接调 `lib/engine`，不再有 `EngineClient`、进程、超时、`probePython`。
宿主那一半（DSH 对话结束的钩子、唤醒定时器、设置页路由）由 `registry.js` 按开关挂上 / 摘下。

## 6. 保什么、砍什么（请过目）

| 功能 | 建议 |
|---|---|
| 情绪 / 关系 / 自主行动 / 事实 / 约定 / 离屏片段 / 作息 / 唤醒 / 常识库 | **保留**，规则照搬，收进内核和四个模块 |
| 记忆层与日记 | **保留，作为 `memory` 模块**，晚一点搬。第一版只保留「汇总」和「日记」两个子代理，「筛选」等真需要时再加；新装默认开 |
| 向量检索（RAG） | **第一版不做**：DSH 没有 embedding 服务，外部接口要 key、要花钱、对话会发出去，本地模型又要一百多 MB；记忆才几十到几百条，关键词 + 时间远近够用。记忆模块里留一个 `recall(query, k)` 接口，第一版用关键词实现，以后要上向量只换这一个实现 |
| 撤销、导出 / 导入、清空数据、命名存档 | **保留**（撤销变成回到快照，更简单） |
| 「按会话一局」的作用域 | **砍掉**，只留全局一局（唤醒线本来就按全局走） |
| 转折（`want_twist`） | 保留，就是把人设里的 twists 原样给出去 |
| 旧库里的 `archive`、`fact_journal`、`thought_debug`、`memory_debug` 等表 | 新引擎不用；导入时只取有用的 |

## 7. 旧存档

写一个一次性导入：读旧的 `engine.db`（`zlib` 解压状态 JSON、读 `facts` 表），转成新格式：

- 她的卡片、心事、关系、事实（含谁知道）、未结束的约定、安排、最近 40 次流水 → 带过来，
  分进内核和各模块切片；
- **游戏时钟换成真实时刻**：旧引擎的「第 d 天第 m 分钟」= 建局时刻 `real_start` + 走过的分钟，
  所以每个 `{day, minute}` 都能换算成一个 ISO 时刻（心事的开始 / 到期、约定的到期、事实学到的时刻、安排的截止）；
  回合号丢掉，流水按原来的顺序配上时刻；
- 记忆条按 `memory` 模块的新格式带过来（模块关着也带，切片放着不动）；
- 各种调试表丢掉；旧库原样留着不删，导入失败可以接着用旧引擎。

在你那份真实的 `engine.db`（800 KB，昨天还在用）的**副本**上先跑通，再给你切。

## 8. 分阶段（每阶段测试全绿再往下）

先跑通一个**最小闭环**（内核 + 情绪 + 两个工具），尽早在 DSH 里真聊、量交账成功率；其余再一块块搬上去。

1. **内核与模块框架**：`core/*` + `registry.js`，拿一个假模块测开关、依赖、`ask` / `emit`、关掉再打开。
   时间相关的测试全用传进去的 `now`：跨午夜、隔三天。
2. **情绪模块**：心事 → 态度 → 自主行动；现有 Python 测试里对应的规则用例逐条翻成 JS，加「关掉情绪、内核照常跑」。
3. **存储与 API**：`store.js`（`node:sqlite`）+ `index.js`；撤销、清空；一次交账在一个事务里的测试。
4. **接上工具，第一次真机**：`soul_state` / `soul_commit` 走新引擎，交账表按第 3 节。
   配置里加 `engine: "js" | "python"`，默认还是 python，随时能切回去。
   先拿上周真实失败过的交账重放，再你在 DSH 里用几天，用 `scan_commits.mjs` 量一次过的比例。
   **这一步没到 90%，先改交账合同，不往下搬。**
5. **唤醒模块**：安排、离屏片段、下一次唤醒、定时器与送达。
6. **常识模块**，以及设置页：路由、页签、模块开关那一排、存档 / 导出导入。
7. **记忆模块**：攒批、汇总、日记、注入（`recall` 用关键词），连同它的页签。
8. **导入旧存档**：在真实库副本上跑通，逐项核对第 0.1 节第 3 条。
9. **切换**：三条验收标准都达到后默认切到 js；再用一阵子没问题，删掉 Python 引擎、`engine-client.js`、
   schema 同步测试，`feat/lite` 分支也删掉（等同于 `memory` 关掉）。
